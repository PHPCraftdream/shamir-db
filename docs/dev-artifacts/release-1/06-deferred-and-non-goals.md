# Отложенное после релиза и то, что СУБД делать не будет

Статус: предложение. Этот файл нужен, чтобы отложенное было записано явно, а не
подразумевалось, и чтобы руководство пользователя честно называло границы
первого релиза.

## 1. Не задача СУБД

### Шифрование данных на диске

Решение владельца (2026-11-11): СУБД не шифрует каталог данных. Доступ к нему
ограничивают политики ОС и шифрование на уровне файловой системы или тома.
Обоснование и обязанности оператора описаны в
`guide-docs/security/data-protection.md` (раздел 1); этот документ остаётся
действующей моделью.

Что СУБД делает вместо этого:

- шифрует резервные копии и логический экспорт — всё, что покидает машину
  (`02-online-backup-and-encryption.md`, `03-logical-dump-restore.md`);
- создаёт файлы с секретами с правами только для владельца;
- шифрует соединения (TLS).

### Доставка копий во внешние хранилища

СУБД пишет копию в каталог или поток. Отправка в объектное хранилище, на ленту,
репликация копий между площадками — задача инструментов оператора.

## 2. Отложено: нужно для зрелой версии, но не для первого релиза

| Направление | Что сейчас | Что нужно | Почему не сейчас |
|---|---|---|---|
| Автоматическое переключение лидера | репликация экспериментальная; выбора лидера, кворума и автоматического переключения нет (`guide-docs/guide/08-interconnect.md`) | выбор лидера с кворумом, ограждение прежнего лидера, обновление без простоя | большая работа с высокими требованиями к корректности; первому релизу достаточно честно описанного режима «один узел и ведомые для чтения» и пошаговой инструкции ручного переключения |
| Восстановление на момент времени | нет | архив WAL поверх физического снимка | требует физической онлайн-копии (R2, вариант А) |
| Обновление без простоя | узлы разных эпох формата не реплицируются | порядок «сначала ведомые», совместимость соседних эпох | зависит от R1 и от работы по доступности |
| Статистика для планировщика | оценка избирательности есть только в векторном поиске с фильтром; общей статистики значений нет | кардинальности и гистограммы значений, выбор индекса по оценке стоимости | нужны данные о реальных нагрузках; метрики R4 дадут основу |
| Квоты на базу и пользователя | ограничение частоты и числа соединений есть; квот на объём данных и время функций нет | квоты объёма, числа запросов, времени исполнения функций | важно для многоарендных установок, а не для первого релиза |
| Онлайн-миграции больших таблиц | — | миграция формата без остановки обслуживания | первая версия R1 выполняет миграции при остановленном обслуживании |
| Обратные миграции схемы приложения | — | откат применённой миграции | рекомендуемый путь — только вперёд и копия перед применением |
| Трассировка | журнал медленных запросов | экспорт трасс (R4c) | вопрос зависимостей и размера бинарника |

Уже записанные в `dev-artifacts/BACKLOG.md` работы (несколько векторных индексов
на таблицу, клиентский интернер в TypeScript-клиенте, удобный интерфейс значений
для процедур) этим планом не меняются.

## 3. Дальний горизонт

Направления, которые есть у крупных СУБД и о которых стоит помнить при
проектировании, но которые не планируются:

- шардирование и распределённые транзакции;
- материализованные представления и непрерывные запросы поверх подписок;
- потоковая выдача изменений во внешние брокеры сообщений;
- пространственные индексы;
- соединения между репозиториями в одном запросе.

## 4. Что записать в руководство к первому релизу

Раздел «Границы первого релиза» в `guide-docs/KNOWN_LIMITATIONS.md` и в
руководстве эксплуатации должен прямо говорить:

1. Высокой доступности нет: один пишущий узел, переключение ручное, порядок
   действий описан.
2. Данные на диске не шифруются; что должен сделать оператор.
3. Откат версии выполняется восстановлением копии.
4. Обновление версии требует остановки обслуживания.
5. Совместимость данных обещана начиная с эпохи первого релиза.

## 5. Отложено: отмена подтверждения транзакции при таймауте процедуры

Таймаут вызова гостя по времени стены может отбросить исполняющийся future
`execute` шлюза во время `commit_tx`: процедура сообщит таймаут, хотя транзакция
подтвердилась. Таймаут не доказывает откат. Это относится к области одного
`db_execute` с `batch_tx()` и этой функцией не устраняется.

Отложено: исполнять транзакционный вызов движка в порождённой задаче и дожидаться
её завершения, а не отбрасывать вместе с таймаутом гостя. Задачу нельзя
отсоединять: она остаётся присоединённой, чтобы исход транзакции и срок жизни
ресурсов были учтены. Это противоречит действующему правилу второй ступени «без
отсоединённой работы» и требует отдельного проектного решения.
