## Changes
1. **G10 regression (trivial, do first).** PR #334 deleted the root re-export `pub use batch::ResultEncoding;` from `crates/shamir-query-types/src/lib.rs` (the enum is still public at `ops/batch/req/result_encoding.rs`). Restore the root re-export (same path style as before: see `git log -p -- crates/shamir-query-types/src/lib.rs`), keep `validate_request_alias_caps`. Add a tiny use of `shamir_query_types::ResultEncoding` in an existing test module so a future removal fails CI.
2. **H5 acceptance — unknown fields rejected.** `BatchOp` decoding currently checks only discriminator names (`batch_op.rs` ~382-414) and delegates to permissive DTOs. The plan row H5 requires: "BatchOp dispatch is unambiguous and rejects unknown fields". Implement rejection of unknown fields in every op body reachable through `BatchOp` (read/write/admin ops, `ReadQuery`, nested option structs that are wire-decoded), with a typed decode error naming the op and the unknown key. Prefer `#[serde(deny_unknown_fields)]` where compatible; it does NOT work together with `#[serde(flatten)]` - where a DTO uses flatten, implement the check explicitly (collect the known keys). Do NOT break any currently accepted wire shape (the TS client builder and `shamir-query-builder` produce these): read the existing golden/round-trip tests; every key the builders emit must stay known. If a DTO legitimately accepts extension keys, list it in the final report instead of rejecting.
3. **RV-QUERY-TYPES-FF6DD2A7.** `FilterValue` uses an untagged derive (alternative trials). Replace with a hand-written `Deserialize` (visitor over the MessagePack data model: nil/bool/int/uint/float/str/bin/array/map) with deterministic dispatch, preserving EVERY currently accepted encoding and the RU7 rule (u64 > i64::MAX stays exact, never a lossy float; see `filter_value.rs:15,45`). Error messages stay typed and short. Tests: one per accepted encoding + negative cases.
4. **RV-QUERY-TYPES-1EC04E32.** `BatchOp` dispatch buffers through MessagePack re-encoding, typed decoding and a linear dispatch chain (~399-418). Remove the re-encode trampoline: buffer once into the serde content representation you already hold and deserialize the selected op directly from it (single pass, O(1) discriminator lookup). Behaviour (ambiguous-discriminator rejection, partial-limit handling) unchanged; existing dispatch tests keep passing.
5. **RU6 test gap (server).** `crates/shamir-server/src/engine/db_handler/tests/misc/record_id_wire_roundtrip_tests.rs:62-82,120-145` claims a handler round-trip but executes DROP through `execute_as` directly. Make the DROP test go through the real handler response envelope and assert a caller-supplied `request_id` round-trips.
