## 11. Risks and open questions for the owner

1. **Durable identity for hybrid:** write `StorageOwnership` into hybrid's durable fjall metadata/interner tier, or accept per-boot minting for hybrid like in_memory? Recommendation: write into the durable tier (identity stability is worth the work); per-boot minting would weaken journal/destruction identity (INFERRED from repo_identity.rs:24-34).
2. **Windows reseed stays unsupported** — destruction + name release supported, reseed not. Accept as documented product limitation? (Recommendation: yes, for this series.)
3. **System-store flush granularity vs crash windows:** the system store is a Fjall `RepoInstance`; `remove_repository` commits via the implicit tx then flushes (**OBSERVED** system_store.rs:330-352) while `remove_database` currently does not flush (:262-275 — fixed in 8b-3c). Confirm the accepted Prepare-flush-then-anchor-flush window and that boot replay tolerates each intermediate ordering.
4. **Supervisor integration contract for lease drain** (Quiesce step): depends on #188's final lease/`stop_all` shapes (**OBSERVED** round 5: supervisor.rs `stop_all` :389, `start_subscription` :428, generation lease under control :434, `reconcile` :311 (**Citation re-verified (round 5)**); **REQUIRES #188** for the lease gate). Decide whether the executor calls supervisor `stop_all`-scoped or a new per-target drain API.
5. **`destination_incidents` location:** system store vs a dedicated journal table/file. Recommendation: system store table for stage 2; revisit if write contention shows up.
6. **Interaction with the online migration API:** migration admits two repos per instance (core.rs field :141-143, `enable_experimental_migration_api` :672+ — **Citation re-verified (round 5)**); confirmed the design routes both admissions through seam (4) — CI should add a migration-during-reserved-name case if the experimental API ships.
7. **Blocked-operation capacity/backpressure:** `Blocked` operations accumulate and hold reservations indefinitely. Recommendation: no automatic expiry; admin-visible listing + explicit abandon-with-reservation-retention (Appendix B archival is owner-approved only) — reservations must never silently lapse (I1).
8. **Audit chain dedup semantics (round 3; revised rounds 4-5):** **DECIDED — the reconciliation-read rule, now through the `AuditSink` seam.** The outbox replay is idempotent by event id `(operation_id, transition_ordinal)`; after an AMBIGUOUS append (error of unknown durability, incl. a failed final sync) the executor calls `AuditSink::contains(event_id)` / `durable_watermark()` — resolved from the appender's persisted log after a FORCED fsync (`read_durable_tail`) or from `checkpoint_durable`'s durable ack record — NEVER `AuditChain::snapshot` (in-memory test helper; a restart starts with an empty in-memory vector, audit_chain.rs:170-177). A found entry counts only after a confirmed durability operation; found-but-unconfirmed or not found → a FRESH successful `write_all`+`sync_all` re-write of the line (a sync error is never proof). The durable-through seq advances only on a contiguous-prefix write+sync; the chain poisons on failure; a torn FINAL tail line is skipped, a torn middle line fails closed (131 §3e item 0b). Chain duplicates are bounded — at most one per ambiguous append — acceptable and documented; the journal, not the chain, is the recovery authority (I10). No dedup index is added to the chain format.
9. **Batched-mode flush-before-return cost:** the barrier call force-flushes the shared audit buffer; a bursty deployment could see latency spikes at Prepare. Acceptable (Prepare is rare, correctness-critical); document the latency characteristic in the audit ops notes.

## 12. Appendix — PR8b-4 sketch: split source coordinates from destination identity

Out of scope for this series; R3 stays a restriction. Today local names ARE upstream addresses: the supervisor resolves targets from durable destination bindings (supervisor.rs; **OBSERVED** round 5: start_subscription :428, generation lease under control :434 (**Citation re-verified (round 5)**) resolving profile Pull streams per (db, repo)), the follower uses the same `db_name/repo` for local lookup and upstream Pull (follower_loop.rs:355-391), and seed install requires manifest source/destination name equality (installer.rs:95-97; seed/catalogue.rs:38-41).

What must change in PR8b-4:

- **Supervisor:** resolve a persisted source→local stream mapping (upstream endpoint/publication + source stream identity + expected source lineage evidence + local destination storage_object_id + binding generation); generation-aware startup.
- **Follower Hello/Pull:** address upstream by source coordinate; bookmark/apply against the local incarnation; fence both independently (hello identity fence :395-427 stays; `fence_pull_identity` at identity_fence/checks.rs:163).
- **Seed install:** drop the same-name requirement; retain the manifest source coordinate in receipts; accept an explicit local target.
- **Profiles:** become source policy separated from placement; publications/stream identity get publisher-owned stable identities so downstream continuity survives local renames.
- **Downstream Hello/Pull:** resolve advertised streams to current local incarnations; preserve continuity across local namespace changes; managed aliases (explicit resources with collision/deletion semantics) if offered.
- **RENAME:** preserves identity, atomic catalogue publication (or durable restart-completable intent — current rename is a best-effort multi-step re-key, **OBSERVED** db_management.rs:139-270/:561-719).
- **Error message:** `replication_destination_bound` for RENAME changes from "format limitation" to the ordinary still-referenced remedy, once identity-preserving rename exists.
