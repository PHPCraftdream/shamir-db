Source: P2 revalidation of the active findings against master `7f04e096`. Read first: `CLAUDE.md`, the card sections in `docs/dev-artifacts/audits/2026-08-14-cross-crate-rush-review/P2.md` (find a card with `grep -n "^### <ID>" <file>`; its file:line references are stale, locate code by symbol), and the verified table in `docs/dev-artifacts/audits/2026-08-14-cross-crate-rush-review/P2-REVALIDATION-2026-10-29.md`.

## Goal

Close the authorization fail-open (a failed group-membership read must deny, not fall through to the Other permission bits), remove the repeated catalogue and settings scans on function invocation, stop materializing the whole interner for every InternerTouch, bound the egress response body, and clean up the facade conventions.

This is one change set for shamir-db: 18 findings, effort units 38 (S=1, M=2, L=4). They are adjacent (same crate, overlapping files), so they are solved together and share tests and review. Contains the only reachable authorization finding (RV-DB-01C2041B): do it first inside the PR.

## Scope

Crates: `shamir-db`. Dependents are type-checked with `cargo check` when a public signature changes.

## Acceptance

- A regression test where the group lookup fails under mode 0704 shows access is denied for both Group and Other read, and a log line carries the context (card 01C2041B).
- Function invocation loads the function metadata once per call and does not repeat the ancestor settings scans (observable through a counter or test seam).
- InternerTouch computes the epoch without materializing the dictionary; explicit-id and publication-gap semantics are unchanged.
- Owner-decision cards are implemented only with a recorded answer.
