## Acceptance (observable)

1. Public API `login({ ... })` for Node (`src/index.ts`) and the browser (`src/browser.ts`), shaped per the spec's client section and the JS0/JS3 design: input username, password, URL (http/https base), token request (`label`, `mode`, `channels`, `databases`, `ttl` only if the spec allows it), cancellation (`AbortSignal`), timeouts; output: the issued token (as the existing redacting `ApiToken` handle) plus its metadata, and a way to continue as a JS3 token client (http or ws) without asking the caller to re-wrap the secret. Do not change existing SCRAM `connect` behaviour or `ConnectOptions` shape for SCRAM callers.
2. Protocol per spec: local username case mapping + NFC; `begin` (msgpack, exact keys, `binding_mode` 0x03), client derives the expected security class from the configured URL and out-of-band policy and refuses mismatches BEFORE sending secrets, KDF lower bounds validated before Argon2, SCRAM proof bound to the frozen scope/label per spec section 2, `finish`, verification of `server_signature` (constant-time where the codebase has a helper), validation of every field of the success body (types, lengths, enums, expiry in the future, label/mode/channels equal to the request), exact status/error mapping to typed errors (wrong password and unknown user indistinguishable as the spec demands, rate-limit with Retry-After, lockout, malformed/oversized body, wrong content type, redirect refused, unsupported server).
3. Secrets: password and every derived key (salted password, client key, proofs) are zeroed/overwritten after use where JS allows (Uint8Array fill), never logged, never in error messages or `cause` chains; the token never appears in errors, logs, `toJSON`, `inspect`. Token expiry later surfaces as the typed error with a re-login hint (reuse the JS1 token-expired error if present; add only what is missing).
4. Browser: only WebCrypto/fetch and the existing browser Argon2 path; no Node modules in the browser bundle graph (extend the existing `token-browser-graph` test style to the login entry). Node: built-in modules only. No new dependencies, no `package.json` version change; `exports` fields only if the design requires, justified in the note.
5. Tests (vitest, under `__tests__/`, multi-line literals): fake `node:http` server speaking the spec wire: success path (compare the derived proof against an independently computed vector or reuse the SCRAM test vectors), wrong password, unknown user (same error), tampered server signature, truncated/garbled body, drop in the middle of the handshake, oversized body, redirect, wrong content type, non-canonical username handling, repeated login, abort during begin and during finish, timeout, token redaction over the whole public surface, browser/Node entry isolation, continuing as http and ws token client with fake transports. No real network beyond a loopback fake server; Argon2 parameters in tests at the minimum the lower bounds allow.

Non-goals: server endpoints (AUTH1), E2E against a real server and docs (AUTH3), new transports, cookie/session semantics, Rust client.
