## DEFINITE defects (each one is a tsc error, a runtime failure or a hang)

1. `entry/ws/token-lifecycle.ts`: the field `handlers` is used at ~85, 88, 93, 113 but never declared (TS2339; `terminate()` throws a TypeError on every close). Add `private readonly handlers = new Map<number, (push: TokenPush) => void>();` to the field block and `import type { TokenPush } from '../../core/protocol/token/ws.js'` (check the real export name).
2. `entry/ws/token-lifecycle.ts` ~98: engine errors arrive as `DbResponse::Error` INSIDE `{rid, res}` (TOKEN_API sections 8 and 10) and `as_of_visibility_timeout` likewise; the lifecycle resolves them as normal results so callers see `protocol_error`. After decoding `res`, if `kind === 'error'` or `'as_of_visibility_timeout'`, reject with the SAME mapping as `appError` in `core/protocol/token/http.ts` (export that function and reuse it; do not duplicate).
3. `entry/ws/token-ws-client.ts` ~72-73 and ~99: `IsolationLevel` includes `'pessimistic'` but the `tx_begin` request variant allows only `'snapshot' | 'serializable'` (TS2345). Narrow `txBegin`'s parameter and reject `'pessimistic'` in `runTransaction` with `TokenTransportError('invalid_request', ...)` before calling it.
4. `entry/ws/token-ws-client.ts` ~33-34: the iterator literal has a `[Symbol.asyncIterator]` member but the field is typed `AsyncIterator<...>` (TS2353). Type the field and the `[Symbol.asyncIterator]()` return as `AsyncIterableIterator<...>`.
5. `entry/token-client.ts` ~37: `FIELDS.subscribe` is `['subscribe']` but `SubscribeOp` also has `deliver`, `initial`, `from_version` (`core/types/stream/subscribe.ts`): any live subscribe with options is wrongly denied. Make it `['subscribe', 'deliver', 'initial', 'from_version']` and add a test.
6. `platform/token/socket-browser.ts` ~84, 119, 122, 127: each of these paths calls `socket.close()` BEFORE `fail(...)`; a synchronous close event settles the setup with `authentication_failed` first. Call `fail(...)` first, then `socket.close()` (as `onError` at ~82 already does).
7. `platform/token/socket-browser.ts` ~108: in `finish`, `notifyClose(event)` stores `terminalEvent` when no close handler is registered, then `cleanupTerminal()` sets it to undefined: a self-initiated close before `onClose` registration is never replayed. Call `cleanupTerminal()` there only when a `closeHandler` was set; otherwise only remove listeners and keep `terminalEvent`.
8. `platform/token/__tests__/socket-browser.test.ts` 46-61: three tests fail because of items 6-7 (not wrong oracles); re-check them after the fix.
9. `platform/token/__tests__/socket-node.test.ts` 8-20: `vi.mock('ws', async () => ...)` returns a class; vitest 1.x requires an object. Return `{ default: MockSocket, WebSocket: MockSocket }`.
10. `entry/ws/__tests__/token-lifecycle-terminal.test.ts` 6-17: every test hangs (12 tests x 90 s): `FakeSocket` drops frames that arrive before a handler is registered (the factory's `queueMicrotask` delivers the binding frame before `onMessage` is set). Buffer early frames in `FakeSocket` like `MemorySocket` in `entry/__tests__/token-ws-client.test.ts` lines 12-14.
11. `entry/__tests__/token-ws-client.test.ts` 29-44: three of four tests fail only because of item 1; re-check after the fix.
12. `entry/__tests__/token-client.test.ts` 17-25: malformed harness: the line `async requestHttp(url, _token, init) {` was replaced by `openTokenSocket: async () => {...},` leaving bare statements in the object literal (parse error, breaks the whole JS1 suite) and `openTokenSocket` is defined twice. Restore the `async requestHttp(url, _token, init) {` header and keep exactly ONE trailing `async openTokenSocket() {...}`. Compare with `git show b07af0c5a:crates/shamir-client-ts/src/entry/__tests__/token-client.test.ts`.
13. `platform/token/__tests__/http-node.test.ts`: the file lost its helpers (the `decode` import, `options`, `msgpackReply`, the `reply.abort` branch of `answer`): dozens of TS2304 and runtime ReferenceErrors. JS2 needs NO change in this file: restore it byte for byte from the JS1 tip: print `git show b07af0c5a:crates/shamir-client-ts/src/platform/token/__tests__/http-node.test.ts` (read-only git is fine) and rewrite the file with exactly that content, then add ONLY what a new `openTokenSocket` member needs, if anything.

## LIKELY defects (fix them too)

14. `platform/token/socket-node.ts` ~24-28: `ALPNProtocols` in a literal returned as `Partial<ClientOptions>` is an excess property for @types/ws `ClientOptions` (TS2353). Return `Partial<ClientOptions> & { ALPNProtocols?: string[] }`.
15. `platform/token/socket-node.ts` ~56/71/79: the same lost-close-event bug as item 7: a self-initiated close before the lifecycle registers `onClose` must be replayed.
16. `entry/ws/token-lifecycle.ts` ~94: a frame without `rid` (for example a `rate_limited` envelope, TOKEN_API section 10 says the connection stays open) is treated as a protocol violation and ends the session. Ignore (count) such frames instead of terminating.
17. `entry/ws/token-lifecycle.ts` ~36/42/56: in the browser every failure before the binding frame becomes `authentication_failed`, including the adapter's `invalid_request` (non-loopback `ws://`), `client_aborted` and `client_timeout`. Let `invalid_request`, `client_aborted` and `client_timeout` pass through unchanged and keep `authentication_failed` only for server-side rejection classes; validate the loopback rule for `ws://` in `createTokenWsClient` before connecting.
18. `entry/ws/token-ws-client.ts` ~145: if `TokenWsLifecycle.connect` rejects, `platform.close()` is never called (agents and listeners leak): close the platform on that path.
19. `entry/ws/token-ws-client.ts` ~108: `registerSubscription` can throw at the 128 cap after `subs[alias]` was set: `runLive` then rejects and the server subscriptions leak. Unsubscribe what was created before rethrowing.
20. `entry/token-client.ts` ~61-75: JS1's `seen.delete(child)` was removed, so the same raw `BatchRequest` object reused in two slots is denied. Restore the JS1 behaviour (compare `git show b07af0c5a:crates/shamir-client-ts/src/entry/token-client.ts`).
