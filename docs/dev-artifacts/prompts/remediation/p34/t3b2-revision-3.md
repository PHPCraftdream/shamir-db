State: revision 2 is committed (4ae90246f). A read-only review found no compile or clippy errors by reading, and these remaining gaps. Paths are under `crates/shamir-server/src/security/perimeter/http_rest/` unless noted. Fix in this order; each fully (code plus its test) before the next.

1. `bucket.rs` (item 4 of rev 2 not fixed): when the cache is full of entries active within the last second, every request with a new token still runs a full `DashMap::retain` (write-locks every shard) and then returns 503. Add `next_sweep_ns: AtomicU64`; sweep only when `now >= next` and a `compare_exchange` to `now + BUCKET_IDLE_NS` wins; otherwise return `Unavailable` at once. Also call a `sweep(now)` from the maintenance gc tick. Also: do not hold the shard guard while `session_from_cached` runs (OS randomness, `Session::for_token`): `Arc::clone` the cached value, drop the guard, then build (hit, Occupied and Vacant paths).
2. `maintenance.rs` `FailureLimiter` (unauthenticated cost): at the cap with no idle entry, each failure from a new subnet scans all 4096 entries before rejecting. Throttle: at most one eviction scan per 100 ms (`last_evict_scan_ns` atomic with CAS); in between reject without scanning. Test: a flood of distinct subnets at the cap triggers a bounded number of scans.
3. Metrics double counting: a request that passed the gate is counted `success` in `authenticate`; if the executor then denies it on scope it adds `forbidden`, so one request has two results in `shamir_token_auth_total`. Move the `success` increment out of `authenticate` into the executor after classification succeeds (so each request yields exactly one result), OR count scope denials in a separate counter `shamir_token_request_denied_total{endpoint}`; choose the smaller change, keep the fixed label vocabulary. Test the choice (see item 8).
4. Exposure drop visibility (security): drops of `api_token_exposed` notices must not be mixed into the failure-summary `dropped` field. Add a separate `exposure_dropped` field to the summary event (and to the details tuple/struct; update test oracles). In `record_exposed`, when `try_send` fails, emit `tracing::warn!` with the token id (known only after MAC verification, safe to log). Drops after the flusher exited or after `disabled` latched must be at least logged once via `tracing::warn!`.
5. Final flush loop: after both receivers are closed, take the drop counters one last time, flush once (exposures in as many batches as needed), then break; do not keep writing back-to-back summaries because late `try_send` failures keep re-arming `flush_requested`. When `stopping && both closed && writer.is_none() && disabled`, break at once (today every shutdown waits the full 2 s when `disabled`). When the 2 s deadline fires with data left, emit `tracing::warn!` with `summary.total`, `exposed.len()`, `summary.dropped` before breaking.
6. Warm-up anchor: use `let a = load(Acquire); if a == u64::MAX { compare_exchange }` so the hot path does not CAS on one shared cache line; and set the anchor once in `RestMaintenance::new` from the clock (spec 8.6: server start), falling back to the lazy anchor when the clock fails.
