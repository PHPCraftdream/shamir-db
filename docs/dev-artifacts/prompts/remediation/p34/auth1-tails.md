## Scope (in this order; each item DONE / PARTIAL / BLOCKED in the report)

1. **Missing acceptance-table tests** (audit rows 5-9): three-way next-BEGIN `Retry-After` parity, 61-second expiry through FINISH, strict last-failure timestamp equality; policy: replicator, token-limit, role-change, FINISH-time read-write/replica recheck; admission: atomic/no-refund, `Dropped` fallback and 503 mapping with existing pending state preserved; classes: class-zero non-loopback rejection; lockout: native <-> HTTP shared pair, HTTP admin unlock.
2. **E2E launches (b) and (d)**: (b) a `read_write` and a superuser-eligible login against a real listener (the eligibility result must be the documented one); (d) TLS plus HSTS plus restart of the listener (state after restart as documented).
3. **S8**: handshake-ID check/insert collision TOCTOU - make the insert the single atomic step with retry on collision; a regression test that forces a collision.
4. **S9 hardening** (all of them where they are code, not wording): `PendingId` must not leak through `Debug`; ID lookup constant-time with respect to the stored value; flat 50 ms padding of a policy BEGIN denial replaced by the documented jitter/ordering; expiry through an ordered queue instead of a scan; in-flight inputs pin their budget buckets; input permits live until the response is written (output accounting); audit-failure classification; remove the unused bound-field workaround; Origin startup diagnostic; correct the deploy shutdown wording in the docs/example config.
5. **S6**: redaction oracle that also sees blocking-thread events and covers BEGIN (not only FINISH).
6. **S3**: a process-wide audit queue budget instead of one queue per listener (design it small; late events after a drain timeout are documented, not hidden).
7. **S5 metrics**: pair-drop reasons (pair-quota / table-full), native/unlock-live occupancy, head totals, real fixed histogram buckets. The pair-drop counters need a hook in `crates/shamir-connect` (lockout pair store): a small public-surface addition is allowed there, with tests; keep it minimal and report it.
8. **N1**: the stop budget (5 s + 2 s) against the listener `request_timeout`: make them consistent (derive the worker budget from the configured timeout or document and test the bound), with a test.

If an item contradicts the server design or needs a production change larger than described, stop that item and put the evidence in the report; never weaken an assertion to match a bug.
