## Scope (in this order; each item DONE / PARTIAL / BLOCKED in the audit)

1. **Response-write permit ownership (S9).** The input permit of a login request is released before the transport writes the response (`crates/shamir-server/src/security/perimeter/http_login/routes.rs`, the `drop(permit)` before `sender.send(reply)`), so the output phase is not accounted. Carry the permit with the reply into `shamir-transport-http` (a guard inside `LoginResponse` or an equivalent owned token released when the body is written or the connection drops), keeping the public transport API change minimal and tested in the transport crate. Add a test that the slot stays occupied until the response is consumed and is released on drop.
2. **Redaction in blocking threads (S6).** The compensation test passes its dispatcher explicitly, which proves nothing. Make the token service's blocking-thread logging inherit the caller's tracing dispatcher (`tracing::dispatcher::get_default` + `with_default` around the `spawn_blocking` body in `crates/shamir-server/src/security/tokens/`), and write an oracle that installs a capturing subscriber the NORMAL way (a thread-default or scoped dispatcher, not handed to the appender) and proves no secret appears from BEGIN and FINISH including the blocking part.
3. **Pending expiry without a full scan on reclaim**: `reclaim_released` scans all cells on every insert/claim; replace it with work proportional to the released entries (the ordered expiry queue already exists), with a test of the bound.
4. **Gauge `shamir_login_http_pair_slots`**: the observer has no decrement on store drop or observer replacement, and several servers in one process can exceed the 8,192 capacity; make the value an absolute, per-store reading (store-owned `AtomicUsize` mirror updated at the insertion/eviction/removal sites under the mutex, `occupied_pair_count` reads it in O(1), the observer reports absolutes) and test it.
5. **Pin budget**: input pins plus pending pins can exceed 3,072 of the 4,096 buckets; size the tables or cap the pins so the sum can never exhaust the table, and test the bound.
6. **Per-listener physical audit queues**: one process-wide queue with the existing logical 1,024-event semaphore, if it stays small and testable; otherwise document precisely why not and leave BLOCKED.
7. Metrics for transport refusals before the login hook (body read, timeouts) counted in the login result metric where the hook can see them; if only the transport sees them, add the minimal hook and test.

If an item contradicts the design or needs a change larger than described, stop that item and put the evidence in the audit; never weaken a test to match a bug.
