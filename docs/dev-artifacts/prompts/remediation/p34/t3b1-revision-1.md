## Fix, in this order

1. Schema shape (TOKEN_API sections 1 and 11, design note `token-api-rest-ws.md` lines ~224-255): the HTTP keys are FLAT on the listener (`kind: http`, `tls: true|false`, `allow_plaintext_remote`, ...), not under a nested `http: {}` block. `ListenerConfig` has no `deny_unknown_fields`, so flat keys are silently dropped today: an operator writing `tls: true` would get a plaintext listener. Make the field `#[serde(flatten)] pub http: HttpListenerSettings` (keep the field NAME `http`, all literals already use it); `deny_unknown_fields` is not supported together with flatten, so drop it on the inner struct. ktav yields i64/u64 for integers through `deserialize_any`, so check the buffered numeric parse works with flatten (read how ktav and the existing config handle other flattened or defaulted numbers; if flatten cannot work, implement a manual two-pass parse and say so). Add parse tests for the FLAT form (minimal and full) from ktav text.
2. `tls` for `kind: http` is REQUIRED (TOKEN_API section 15) and must be absent for the other kinds: make it `Option<bool>` (or an equivalent that distinguishes absent from false); validation errors: missing on http, present on tcp/ws/unix; also reject `profile` on `kind: http` (it is "absent for http"; today it is silently accepted and a `tls_exporter` profile on an http listener serves plaintext), and reject any non-default http-only key on other kinds (the first run's tests even do that: fix them).
3. `allow_self_signed` (TOKEN_API section 11, design :239): add the config field and its default and document it; the runtime refusal and SPKI print belong to T3b-3, say that in the field doc.
4. `http_mapping.rs` (settings -> `HttpServerConfig`) fails open: it sets `tls: None` even when `settings.tls` is true, `forbidden_body` is empty bytes (section 9 requires a msgpack `DbResponse::Error` body on 403) and `ping_body` is empty (the transport hands it to the executor as the Ping request, see `crates/shamir-transport-http/src/server/service.rs`). Change the signature to take `tls: Option<Arc<rustls::ServerConfig>>`, `forbidden_body` and `ping_body` as parameters (at most 7 parameters), return an error when `settings.tls` does not agree with `tls.is_some()`; test that `tls`, `hsts` and `write_timeout` are mapped.
5. Test oracles (the review found these fail): `src/boot/config/tests/http_listener_tests.rs` around lines 89-91: with `tls = true` the plaintext flags are still true and validation correctly refuses; clear both flags before the `is_ok()` step, then set one and assert the error. `tests/admin/ops/config.rs`: the `kind: http` listener inherits `head_timeout_ms` = 5000 from `auth_init_timeout_ms`, which exceeds `request_timeout_ms: 1000` and fails validation: use `request_timeout_ms: 10000` or set `head_timeout_ms`; the test replaced the tcp/plain 127.0.0.1:7334 listener with the http one so the listener count and indices asserted afterwards are off by one: re-add the plain tcp block after listener 0; restore the lost `assert_eq!(cfg.listeners[0].addr, "0.0.0.0:7331")` assertion.
6. Validation oracles are too weak (`is_err()` only, and several steps would fail for the non-loopback rule anyway): assert message substrings and make each step exercise exactly one rule. Add the missing cases: zero body/request timeout, `body_timeout_ms > request_timeout_ms`, bad CIDR address, prefix over 32/128, tcp/ws without `profile` ("requires profile"), the launcher's "not wired yet" error for an http listener, a `kind: http` block parsed from ktav (minimal and full).
7. The timeout validation message must include the effective head/body/request values and where the head value came from (`security.connection.auth_init_timeout_ms` inheritance).
8. Cleanups: remove redundant `l.kind != ListenerKind::Http &&` after the early return in `boot/config.rs` and prefer `let Some(profile) = l.profile else { return Err(..) }`; `http_validation.rs` is a one-line forwarder: fold it into `http_listener.rs` ONLY if you can delete nothing (you cannot delete files: then keep it and give it real content or leave it and list it for the orchestrator); update the module doc of `boot/config.rs` (schema and validation rules) to mention `kind: http`; docs on `HttpListenerSettings::validate`.
