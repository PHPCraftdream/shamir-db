# TOKEN-T3b-3 revision 1 - findings of the compiler-style review

State: commits e7123d0e2 (+ merge of T3b head) and 3359d11ba (clippy fixes found by the fork CI). The review found no compile/clippy/layout errors by reading; the findings below are runtime and test-quality defects. Read `t3b3-launcher-wiring.md` and the note `docs/dev-artifacts/audits/2026-11-02-token-t3b3-wiring/DESIGN.md` first, then CLAUDE.md. Fix in this order, each with its test.

1. P1 - HTTP shutdown bound. `crates/shamir-server/src/engine/server/server_handle.rs:192-196` awaits each HTTP listener task plainly; after cancel `serve` (`crates/shamir-transport-http/src/server/accept.rs`) waits up to `cfg.limits.request_timeout` (default 120 s, `boot/config/http_listener.rs:152`) while the runtime shutdown deadline is 30 s (`boot/runtime.rs:19`): one slow request cuts `shutdown_with_report` mid-join (no repository flush, no store release, exit 70). Native connections use `CONN_DRAIN_TIMEOUT` (10 s) + `CONN_ABORT_TIMEOUT` (2 s) and write an error into the report; HTTP does not. Fix in `shutdown_with_report`: join all listener tasks against ONE shared deadline `Instant::now() + CONN_DRAIN_TIMEOUT` with `tokio::time::timeout_at`; keep `task.abort_handle()` before awaiting; on timeout `abort()` and wait up to `CONN_ABORT_TIMEOUT`; record `report.add_error(format!("HTTP listener drain exceeded {CONN_DRAIN_TIMEOUT:?}; aborted"))` (use the report API that exists, read it); AND the outcome into `quiesced` so the repository flush is skipped exactly as on the native path. Apply the same bound to the two rollback copies (`server_launcher/listeners.rs` around the rollback at ~382-386 and `launch.rs` ~849-851). Test: an e2e test with a request that stays open (a body that is never completed within the test window, short `request_timeout_ms` is NOT to be used to hide the bound) proving shutdown returns within the drain bound and the report carries the error.
2. P2 - weak oracles. (a) `tests/e2e/http_rest/rails.rs:46-77`: the write half inserts into a table that was never created and passes on any error mentioning "table". Create the table first (through the native seed harness `launch_with_native_seed` plus `shamir_client`, as `tests/e2e/http_rest/lifecycle.rs:140-160` does) and assert a successful batch/insert response so the test proves the write rail opened. (b) The token session is `Session::for_token` with `superuser = false` and roles from the token record: in `tests/e2e/http_rest/common.rs` issue the test tokens with the owner's real roles (as the CLI does, `security/tokens/cli/create.rs:46` `owner_roles: owner.roles`) so the owner read in `lifecycle.rs` cannot fail on access. (c) `http/tests/proxy_tests.rs:67-71` `headers_over_limit_fall_back_to_tcp_peer`: 8193 `'a'` falls back even without the 8 KiB cap; build more than 8192 bytes of VALID entries (e.g. `"198.51.100.1, ".repeat(N)` with the trailing separator trimmed) so only the cap makes it fall back.
3. P3 - Windows flake class. The e2e tests assert `report.is_clean()` after shutdown; `is_clean()` includes the repository-flush budget, which is disk-speed dependent on Windows runners (see the comment at `src/tests/boot/server_tests.rs` around the GC test and the WIN-FLUSH note in `docs/dev-artifacts` if present). Use `assert!(report.errors().is_empty(), "{report:?}")` in every e2e test except those whose subject is shutdown itself (the keep-alive + restart test); raise that test's 15 s shutdown timeout to 30 s. Do not touch the unit test at `src/tests/boot/server_tests.rs` `launcher_shutdown_stops_token_gc_task` (another branch owns it).
4. P4 small items: (a) `server_launcher/listeners.rs` ~185-378: the `for` body inside `let result = async { ... }` was never re-indented; move the loop into a helper `async fn ... -> Result<(), BootError>` or re-indent by hand so rustfmt really formats it (check `cargo fmt -p shamir-server -- --check` after). (b) `listeners.rs:259` `(ListenerKind::Http, _) => continue` sits after `bound_ipc_paths.push(None)`: make it `unreachable!("HTTP handled at loop entry")` as the other arm does. (c) `http/launcher.rs` ~248-262: build the TLS 1.3 server config BEFORE `tokio::spawn`, so a TLS configuration failure is returned from `launch()` instead of only being logged by the spawned task. (d) `http/proxy.rs` ~333-369 and `Cidr::contains`: normalise IPv4-mapped peers and forwarded addresses with `IpAddr::to_canonical()` (dual-stack `[::]` binds deliver IPv4 as `::ffff:a.b.c.d`), with a test. (e) `deploy/server.example.ktav:87` still says "HTTP listener startup is not wired yet": update the text. (f) `tests/e2e/http_rest/common.rs` `seed_owner` opens the fjall `users` store, drops it and the launcher reopens it at once: prefer bootstrapping through the launcher and reading the owner id afterwards if that is simple; otherwise leave it and say so.
