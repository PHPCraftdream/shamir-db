## Goal

Unchanged from the original brief, sharpened: from before the source drain until the rename is resolved, the source table accepts no write AND no DDL or metadata change through ANY path (name lookup, token lookup, a stale `TableManager` clone obtained before the rename, the tx commit pipeline, an admitted DDL twin, cancellation of the rename future). When `persist` fails, the engine rolls forward (`Committed`), rolls back (`NotCommitted`, only when provably safe), or fences the pair as "rename in doubt" until a retry of the same rename or a restart resolves it. Because the source is frozen and detached from before the drain until resolution, and the drain covers every version allocated before the freeze, the copied stores equal the source at every durable outcome, so whichever outcome boot replay picks is lossless.

- **Q5 - right.** Boot (`shamir_db/core.rs:349-403`) registers one config per catalogue row; a destination-only row yields only the destination. ## Decisions taken (orchestrator-owned; original decisions 1-9 stay in force except where amended here)

- **R1 - Detach gate (new; closes stop A).** Add to `TableManager` one field `detached: Arc<AtomicBool>` (shared by `Clone`, `false` in every constructor: the three struct literals in `table_manager.rs` (`Clone` impl, `#[cfg(test)] new`) and `write_domain_barrier.rs` (`open_with_domain_admitted`); re-check with `rg -n "in_flight_creates:" crates/`). Methods (in `barriers/ddl_barriers.rs`, next to the freeze): `pub(crate) fn detach_for_rename(&self)` (store `true`, `Release`), `pub(crate) fn reattach_after_rename(&self)` (store `false`, `Release`), `pub(crate) fn ensure_attached(&self) -> DbResult<()>` (load `Acquire`; `true` -> `DbError::MigrationFrozen { table: self.name.clone() }`). The flag is only ever written under the repository permit and only ever read AFTER the reader acquired the permit, so the permit mutex orders them; there is no hot-path cost (CRUD and commit never read it). Call `ensure_attached()?` (a) in `TableManager::admit` (`write_domain_barrier.rs:39`) right after the permit is obtained (the permit is dropped by `?`), which gates every public non-admitted DDL/maintenance wrapper at once; (b) as the first statement after `debug_check_permit` in every Q10 method marked "explicit". Exempt (document each in the note): `begin_write_barrier_admitted` (infallible signature; its only callers resolve the table by name under the same permit, which R2 fences), `begin_migration_freeze_admitted` (the freeze bit itself rejects a second claim), open/construction (`create_with_domain_admitted`, `open_with_domain_admitted`, `recover_hash_renames_admitted`, `rerun_identity_migration_admitted`, `ensure_base_identity_current`), and the repo-shared interner twins `persist_interner_admitted` / `intern_query_value_admitted` (the interner is per repository, not per table store). Every other mutating twin in the Q10 list gets the explicit check, including at least: `create_index_admitted`, `create_unique_index_admitted`, `drop_index_admitted`, `drop_unique_index_admitted`, `drop_index2_admitted`, `create_index_v2_admitted`, `create_sorted_index_with_include_admitted`, `drop_sorted_index_admitted`, `rename_index_admitted`, `repair_admitted`, `set_buffer_config_admitted`, `add_validator_binding_admitted`, `remove_validator_binding_admitted`, `write_ddl_op_status_admitted`, `drop_all_indexes_for_table_removal_admitted`, `seed_current_versions_admitted`, `reset_and_populate_index2_admitted`, `seed_log_from_data_store_admitted`, `bulk_populate_index2_admitted`, `replicate_interner_from_admitted`, `replicate_index2_descriptors_from_admitted`, `begin_write_barrier_with_permit`. Rejected alternatives (record in the note): holding `ddl_admission` in the fence (deadlock, Q1); checking `MIGRATION_FREEZE` in DDL (breaks the migration coordinator's own barrier DDL on its frozen source, `admin_migration.rs:460`, and changes migration semantics); a new barrier bit (u8 selector space is full; touches `shamir-index`). The wire code stays `table_migrating` for a stale handle, matching the data-write rejection of original acceptance 2.
- **R2 - Name fence scope (amends original decision 3).** The fence registry stays (owned entries, no mutex): `rename_fence: Arc<scc::HashMap<String, RenameFenceEntry, THasher>>` where `RenameFenceEntry` is `Source(RenameInDoubt)` under the `from` key and `Destination { from: String }` under the `to` key, plus `rename_fence_len: Arc<AtomicUsize>` as the O(1) mirror (no `scc` `len()`). `RenameInDoubt { from: String, to: String, source: TableManager, freeze: MigrationFreezeGuard }`. Every fence mutation (raise, take, clear) happens under the repository permit, so "take" is `remove_sync(from)` + `remove_sync(to)` with ownership moved out (no one-shot slot, no `std::sync::Mutex`). Checks happen in: `RepoInstance::get_table` (before the `initialized_table` fast path; skip the map read when the mirror is 0), `get_table_admitted`, `add_table_admitted`, `remove_table_admitted`, and the rename transitions (a different pair touching either name -> conflict). The check returns `DbError::Conflict(format!("rename in doubt: '{from}' to '{to}'"))` (stable prefix `rename in doubt:`). **NOT fenced:** `table_by_token`, `table_by_token_if_live`, `table_by_token_admitted`. They must resolve through a private unfenced inner lookup (split `get_table` / `get_table_admitted` into a fenced public wrapper and an unfenced `pub(super)` / private body; `table_by_token*` call the body). Reason: a `None` from `table_by_token_if_live` would skip the prelock barrier check (`prelock.rs:263-284`) and let a tx materialise into the frozen source, and an `Err` from `table_by_token` stalls the drainer's replay prefix for the whole repository (`drain_step.rs:231-249`). On the token paths the freeze bit is the gate: they get the frozen source and every write through it fails with `MigrationFrozen`. Reads by name during the in-doubt window fail with the conflict (retryable); that is accepted.
- **R3 - Visibility wait before the drain (new; closes a lost-write window the original design did not).** In every transition, after the freeze is held and before `drain_to_history`: read the largest version allocated so far (Q7 names the exact call), then `tokio::time::timeout(RENAME_VISIBILITY_WAIT, gate.await_visible(v))`. `Visible` -> continue; `ReopenRequired` -> fail with `DbError::RepoRequiresReopen(..)`; timeout -> fail with `DbError::Conflict(format!("rename visibility wait timed out for '{from}'"))`. Both failures happen before `persist`, so they follow the pre-persist rule of R6. `RENAME_VISIBILITY_WAIT` is a private const: 30 s, and 200 ms under `#[cfg(test)]` (two `cfg`-gated consts, no runtime config). The timeout is what makes this deadlock-free: a committer that could ever wait on the repository permit while holding an allocated version (Q3 found none) only makes the rename fail retryably.
- **R4 - Counter flush before the copy (new, one call).** After the drain and before the copy, under the permit: `source.counter().persist_admitted(permit).await?` so the copied `__info__` carries the live record count (today a dirty count is lost to the destination).
- **R5 - Cancellation-safe attempt (new).** Put the in-flight state in a RAII type `RenameAttempt<'p>` (own file) that borrows the permit (`&'p RepoWritePermit`, so it cannot outlive it and drops before it) and owns `source: TableManager`, `freeze: Option<MigrationFreezeGuard>`, the pair, `was_fenced: bool` and a phase (`Preparing` / `Persisting`). Explicit endings consume it: `commit(self)` (retire the freeze, keep `detached`, clear the fence), `abort(self)` (only legal when `!was_fenced` and the phase is `Preparing` or the outcome is `NotCommitted`: `reattach_after_rename`, then drop the freeze), `into_doubt(self)` (insert the fence entries, increment the mirror). Its `Drop`, when no ending ran (the future was cancelled or a `?` escaped): phase `Persisting` or `was_fenced` -> behave as `into_doubt`; otherwise -> behave as `abort`. `Drop` must stay synchronous (`insert_sync`, atomics only, no `.await`). Set the phase to `Persisting` immediately before the `persist(..)` future is created.
- **R6 - When `NotCommitted` may unfreeze (amends original decision 2).** `NotCommitted(e)` rolls back (reattach, drop the freeze, return `Err(e)`) ONLY on a fresh attempt (`!was_fenced`) in the normal branch. On a retry of a fenced pair it is treated as `InDoubt` (the earlier attempt's catalogue change may still replay at boot; Q2). Any error that escapes before `persist` follows the same rule (fresh -> abort; fenced retry -> back into the fence, return the conflict that wraps the error).
- **R7 - Recovery branch (amends original decision 5's last sentence).** In `recover_table_rename_with` the destination row is already visible, so every non-`Committed` outcome of `complete_table_rename_row` (pre-commit errors included) is `InDoubt`; the recovery closure never returns `NotCommitted`. When the source is registered and not fenced (pre-03c leftovers), the recovery branch freezes and detaches it exactly like a transition before calling `persist`.
- **R8 - Retire keeps the handle dead (extends original decision 4).** On `Committed` the old source keeps both the retired freeze bit and `detached = true` forever: its clones reject writes and DDL with `MigrationFrozen`.
- **R9 - Repo-rename guard (narrow exception to original decision 9).** `ShamirDb::rename_repo_as` refuses, after its existence guards and before any mutation, with the `rename in doubt:` conflict when the source repository has any fence entry (`RepoInstance::has_rename_in_doubt(&self) -> bool`, mirror > 0). No other repo-rename change.
- **R10 - Wire code.** `handle_rename_table` keeps the message and passes `code: e.code().map(str::to_owned)` so the in-doubt conflict reaches the wire as `tx_conflict` and a frozen-source error as `table_migrating`.
- **R11 - Interim safety.** Until the `SystemStore` split of original decision 5 is in place, the `table_management.rs` closures map every `persist` error to `InDoubt`. That state is already safe (no lost write); the split only restores availability for pre-commit failures. Land the safety core first (Order of work).
- Original decisions 2 (enum and engine semantics, as amended by R6/R7), 4 (`retire` with a private `armed: bool`, no `mem::forget`), 5 (split of `rename_table_row`, `resolve_table_rename`, success path read count stays 2), 6 (retry convergence), 7 (`durability_tail_faults` countdown seam), 8 (existing tests change shape, not intent) stay as written.
