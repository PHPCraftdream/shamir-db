## Scope (in this order; each item DONE / PARTIAL / BLOCKED in the audit under "Tails 3")

1. **Pin budget by unique buckets.** The budget is 3,072 pinned buckets (input pins plus pending pins) of 4,096 per table. Count UNIQUE pinned buckets, not leases: in `pin` reserve one unit only when a bucket marker goes 0 to 1 (`fetch_update` with a cap of 3,072 on the budget counter; on refusal roll back the markers already incremented and their units); in `BudgetPin::drop` release a unit only when a marker goes 1 to 0; `Clone for BudgetPin` only `fetch_add`s the markers (a 0 to 1 transition is impossible there). No lease object. A refusal maps to `ServerBusy` (fail closed) and records `record_budget_drop("pin_budget")`. A FINISH of a source that already pins its bucket through its pending entry must cost nothing. Tests: the bound is exactly 3,072 unique buckets; clone and drop do not drift; two clones of one pin release once; a refused pin leaves the counters unchanged; `admit` of an already pinned source still succeeds at the cap. The half-finished version of this item was reverted on purpose (the lease design counted leases and refused legitimate traffic at about 512 concurrent logins) - do not reintroduce it.
2. **End-to-end test of the response hold** in `crates/shamir-transport-http` (`login_routing_tests`): a handler returns `LoginResponse::with_hold(DropSignal)`; through `handle_login` + the service + `GuardedIo` over a small duplex: the hold is NOT dropped until the client has read the whole response; it is dropped exactly once after; and exactly once when the connection is aborted by a stalled client. Also add `GuardedIo::release_holds()` and call it right after `into_parts()` in `accept.rs`, before the drain and linger, so a dead connection does not keep the login slot for up to `LINGER_DEADLINE`; test it.
3. **Double counting.** A handler timeout in `route_handler` calls `refused(408)` while the detached application worker later records its own result for the same request: after a request has been handed to `handle`, the transport must not count it again (the outcome belongs to the application); keep counting refusals made BEFORE `handle`. Unify `result_for_status` and the application `refused` mapping into one function (the tables diverge for 408/431). Tests for each path (counted exactly once).
4. **Blocking-thread dispatcher in `tokens/store.rs`**: the `spawn_blocking` calls (store.rs around the listed lines) log outside the caller's dispatcher; capture `tracing::dispatcher::get_default(Clone::clone)` before and re-enter with `with_default` around the whole body, as `token_service.rs` and `gc.rs` already do; extend the redaction oracle if it can cover it.
5. **Gauge `shamir_login_http_pair_slots`**: two threads can publish absolute values out of order after the mutex is released; publish the absolute value while the store mutex is held (the observer is a non-blocking `gauge.set`) or drop stale publications with a version counter; fix the stale comment about "deltas" in `launch.rs`. Test the ordering with a recording observer.
6. `holds.send(..).await` in `service.rs` has no deadline (the REST path wraps its body in `timeout_at`): use `try_send` (a failed send means the connection is already dead, drop the hold) and remove the needless `into_parts`/`from_parts` round trip if it is not needed.

If an item contradicts the code or needs a larger change, stop that item and put the evidence in the audit; never weaken a test to match a bug.
