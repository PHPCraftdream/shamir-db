## Items (in this order)

1. **Password change revokes the owner's tokens** (rows HTTP, WS, HTTPS, WSS "owner password changed" and "Issuance: password change revokes tokens"): find in the server how an ordinary user changes the password (`ChangePassword*` request over the SCRAM channel, see `TOKEN_API.md` and `crates/shamir-server/src/security/`), drive it through a real SCRAM client like the existing issuance tests, then assert a REST token gets 401 and a live WS/WSS token session is closed with 4011.
2. **Owner roles changed over WSS** (row WSS "owner roles changed"): mirror the plaintext WS test in `crates/shamir-server/tests/e2e/http_ws/revocation.rs` over TLS.
3. **Unsigned-HMAC control for `for_user` issuance**: a superuser issuing for another user without the HMAC confirmation is rejected, with the documented error code; reuse or extract the raw fixture that the signed case uses (`suite/issuance.rs`), do not duplicate it.
4. **Privilege sweep over real sockets** (rows "Privilege: ..."): the server classifier is private, so do not wait for a seam; build the request lists in the test and make drift a compile error: write a function with an exhaustive `match` (no wildcard arm) over every `DbRequest` variant and another over every `BatchOp` variant that classifies each as `admin-denied` or `data` in the test; a new variant then fails to compile and forces a decision. Against superuser-owned and replicator-owned tokens send one request per admin variant (built with `shamir-query-builder` / the typed constructors, never raw JSON) and assert the documented denial; `ListDatabases` / `ListUsers` / `AccessTree(db)` follow the scope rules in `scope.rs` (denied only outside the token's database allowlist - assert exactly that, both allowed-in-scope and denied-out-of-scope), `Repl` and `ChangePassword*` are denied. Mind the failure limiter: one denial per request is a 403 (authorized token), not an authentication failure, so the sweep does not hit the limiter; assert that assumption in the first case.
5. **Revoke race, deterministic**: N workers loop REST requests with the token while the test revokes; use an atomic flag set only AFTER the revoke call returned; every request that STARTS after the flag is seen set must be 401 (record start-after-flag per request, no sleeps); for a WS session send frames after the revoke returned and assert there is no successful response and the close is 4011. Bounded deadlines everywhere.
6. **Wire-level "secret exactly once"**: assert on the raw serialized create response that the full token string occurs exactly once and that a following `list` response (raw bytes) contains neither the full token nor its secret segment.
7. Rows that stay BLOCKED (response-byte guard, SCRAM store absence, Windows/Linux CI): leave them BLOCKED with the reason; do not add production seams.
