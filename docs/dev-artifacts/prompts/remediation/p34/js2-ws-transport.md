# TOKEN-JS2 - shamir-client-ts: token WebSocket/WSS transport for Node.js and the browser

Sources, read in this order: `docs/dev-artifacts/design/token-client-js.md` (accepted design note of stage JS0: sections 1, 2, 3, 4, 5, 6, 7, 9 and 10; the "Proposed spec amendments" at its end are already applied to the spec), `docs/guide-docs/client-server-protocol-spec/TOKEN_API.md` (normative: section 5 verification, 8 error codes, 10 WebSocket for both endpoints, the browser first frame, the binding frame, envelopes, close codes and socket accounting, 11 transport security), `TRANSPORT_WS.md` (close codes with the token exceptions, heartbeat and frame limits, Origin), `SUBSCRIPTIONS.md` (`PushEnvelope`), `CLIENT_BROWSER.md`, then the code you extend (stage JS1, already in this branch): `crates/shamir-client-ts/src/{core/protocol/token/*, platform/token/*, entry/{api-token,token-client,token-db,token-response,token-ddl-state}.ts}`, and the existing SCRAM client pieces you may reuse by import but must not grow: `src/core/client/{client.ts,cursor-iterator.ts,subscription-handle.ts,subscription-router.ts,db.ts}`, `src/platform/{node,browser}.ts` (the `ws` package is already a runtime dependency), `src/core/support/errors.ts`, `CLAUDE.md`.

## Goal

A working, tested-by-design token WebSocket client for BOTH runtimes. Given a bearer token and a `ws://`/`wss://` origin the user gets `TokenWsClient` (design note section 1): `ping`, `execute`, `executeWithTouch`, `waitForVisibility`, `getDdlOpStatus`, `db(name)` whose `TokenWsDb` adds `cursor`, `tx` and `runLive` (subscriptions). Node connects to the native endpoint `/shamir/v1/ws` with `Authorization: Bearer <token>` and sends no token frame; the browser connects to `/shamir/v1/ws/browser` and sends the token as the sole first binary frame. This stage is the WebSocket path only.

In scope (layout from design note 10.1; count the entries of every folder you touch with `ls` before and after: at most 7 direct entries per folder, at most 1000 lines per file, tests under `__tests__/`, never grow `src/core/client/client.ts`; `core/protocol/token/` and `entry/` are at six entries each, so one new file fits and a second needs a subfolder):
- Platform seam: extend `TokenPlatform` (JS1 `platform/token/types.ts`) with `openTokenSocket(url, token, opts)` returning `TokenSocket` (design note section 2: `send`, `onMessage`, `onClose` with `{code, reason, wasClean, error?}`, `close(code?, reason?)`; early messages are buffered, bounded, until the handler is registered). Node adapter `socket-node.ts` (the `ws` package, client-owned, subprotocol `shamir-v1`, `Authorization` header, TLS 1.3 minimum, per-client CA, `allowInsecureTlsForDevelopment` as the only bypass, optional `Origin`, `perMessageDeflate: false`, `maxPayload` 16 MiB, connect timeout and `AbortSignal`, no token frame). Browser adapter `socket-browser.ts` (native `WebSocket`, subprotocol `shamir-v1`, `binaryType: 'arraybuffer'`, endpoint path `/shamir/v1/ws/browser`, no Node imports; the token is never placed in the URL, the subprotocol list, cookies or headers; plain `ws://` is refused before opening unless the host is loopback).
- Codec `core/protocol/token/ws.ts`: the browser first frame (exactly one msgpack map with the single key `token`, 80 bytes for a canonical token, built without leaving the token in long-lived strings where avoidable), the binding frame `{ok: true, sid: bin(32), expires_at_ns}` (validate strictly: `ok` is `true`, `sid` is exactly 32 non-zero bytes, `expires_at_ns` a positive integer, no unknown keys; keep nanoseconds as `bigint`), request/response/error envelopes `{sid, rid?, req}`, `{rid?, res}`, `{rid?, error}` (`req` and `res` are msgpack-encoded bytes), `PushEnvelope` decoding, response validation before any public cast.
- Lifecycle `entry/token-lifecycle.ts`: connect = open + (browser: send first frame) + wait for the binding frame within `connectTimeoutMs` (default 10,000 ms; zero disables), rid allocation and correlation (u32, never reused while pending, out-of-order responses), per-request timeout (default 35,000 ms) and abort, push demultiplexing into subscriptions, close-code mapping to `TokenTransportError` (extend the closed `TokenTransportErrorCode` union in `errors.ts` only as needed: `4000` generic authentication failure, `4010` sid mismatch, `4011` revoked, `4012` expired, `4013` channel denied, `4014` plaintext write denied, `1013` server busy, `1000` normal, `1003`, `1009`, abnormal close, network, protocol violation; before the binding frame every browser-side failure is reported with the same public class), terminal lifecycle (reject every pending request, end cursors and subscriptions, clear timers and queues, idempotent `close()`), `expiresAtNs` and `sid` exposed read-only. No reconnect, no retry, never replay a write.
- `TokenWsClient` and `TokenWsDb`: share the JS1 `TokenHttpDb` behaviour by composition or a common base (do not duplicate it); `executeWithTouch` delegates to `execute` and never calls the SCRAM interner-touch helper; all requests name-keyed, `query_version: 4`, no interner fields. `cursor` (`CreateCursorRequest`, `FetchNextRequest`, `CancelCursorRequest`, reuse the existing `CursorIterator` semantics), `tx` (`tx_begin`, `tx_execute`, `tx_commit`, `tx_rollback` with `tx_handle`, same closure semantics and result types as the SCRAM client; rollback on closure failure and on terminal close), `runLive` returning `{response, subs}` with `TokenSubscriptionHandle` (`next()`, `unsubscribe()`).
- An internal factory (for stage JS3) such as `createTokenWsClient(options, platformFactory)`; do NOT touch `connect()` overloads or the `src/index.ts` / `src/browser.ts` exports beyond what is strictly needed to compile, and say in your report what you left for JS3.

Non-goals: login (AUTH2), public `connect` overloads and package exports (JS3), end-to-end tests (JS4), docs (JS5), server changes, new dependencies (stop and report if one is unavoidable), reconnect, retry, token refresh.

## Tests (write them, you cannot run them; vitest, `__tests__/` folders, one topic per file)

Prefer an in-memory fake `TokenSocket` pair for lifecycle tests (no network). Node adapter tests may use a local `ws` server from the existing dependency: `Authorization` header present, subprotocol `shamir-v1`, no frame sent by the client, CA and development-bypass plumbing, connect timeout, abort, `maxPayload`. Cover: binding validation (every malformed variant), rid correlation including out-of-order and unknown rid, early-message buffering and its bound, request timeout and abort, every close code mapping (`4000`, `4010`-`4014`, `1013`, `1000`, `1003`, `1009`, abnormal), pending requests rejected on terminal close, cursors/transactions/subscriptions cleaned up on terminal close, push demultiplexing and `unsubscribe`, idempotent `close()`, the browser first frame (single key `token`, 80 bytes, binary, sent once, never in URL, subprotocol or headers), refusal of non-loopback `ws://` for the browser, no `node:` import in the browser adapter graph (a module-graph test over the source files is acceptable), redaction of the token everywhere (errors, JSON.stringify, util.inspect, template strings), `executeWithTouch` makes no interner call, requests are name-keyed with `query_version: 4`.
