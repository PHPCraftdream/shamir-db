## Scope of this slice

New code in ONE new folder `crates/shamir-server/src/security/perimeter/http_rest/` (the parent has 3 entries; the new folder must itself stay within 7 entries; tests in a `tests/` subfolder or the existing tests convention of the crate, one topic per file). Nothing in this slice starts a listener or touches `launch.rs`, `listeners.rs`, `boot/config.rs` (other slices own them).

- The gate: an implementation of `shamir_transport_http::TokenGate` over `TokenService::verify` (header bytes from `AuthHeader`, `Endpoint::Rest`, current clock), returning the `GateDecision` variants with the uniform 401 for every failure class of TOKEN_API section 5, 403 with the application error code for verified-but-denied cases, 429/503 where section 8 names them; `still_valid` revalidates the grant against the service/mirror (revoked, expired, owner floor) without touching storage. Counters from T2b (`TokenCounters`) are used, not duplicated.
- The executor: an implementation of `RestExecutor` that decodes the msgpack request, applies the allowlist of TOKEN_API section 7 (deny by default; ONE closed enum of permitted operations; databases allowlist of the token; mode read_only/read_write; the plaintext-write rail given as a plain boolean input), runs the request through the SAME handler path as a native connection under the token owner's principal and roles snapshot via a `ScopedHandler` wrapper type that owns the scope checks and delegates to the existing handler (find how a `DbRequest` is executed for a session: `DbHandler`, `handle_request`, the coarse gate and the per-operation permission checks; no duplicate permission logic), maps the outcome to the response body and `ExecStatus`, keeps the hold value until the response has been written, and never returns the token, MAC or internal error text.
- Audit, metrics and logs of TOKEN_API section 13 for this path (fixed-vocabulary labels, no secrets, no peer-controlled strings), using the T2b counters, the existing audit writer and the metrics registry.
- A single constructor-style entry point (for T3b-3) that builds the gate and the executor from `Arc<TokenService>`, the handler, a clock and the rails; document it.
- Tests (you cannot run them): the gate decision table (every failure class of section 5 yields the same 401 body and status; revoked, expired and owner-floor cases; channel and mode denials; plaintext-write rail), the executor allowlist (every permitted operation, a representative sample of denied ones including admin and token-management operations, database allowlist, read-only mode rejecting writes with the specified code), body and status mapping, secret redaction in errors and logs. Use `TokenService` with temp directories as the T2b tests do.
