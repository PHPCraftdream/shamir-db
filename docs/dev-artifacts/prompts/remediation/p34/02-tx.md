Make the legacy plain-store publisher monotonic, stop history_of from reporting a storage failure as an unknown age (GC keeps its conservative lookup), correct the VERSION_SEP codec-domain tests and prose, refresh stale scaffold documentation, and handle the A10 barrier versus GC starvation design-first.

This is one change set for shamir-tx: 8 active findings, effort units 20 (S=1, M=2, L=4). They are adjacent (same crates, overlapping files), so they are solved together and share tests and review. Decisions marked IMPLEMENT were taken by the design decider (@oh) on 2026-10-30 and are binding; SKIP means the card is accepted as it is; ESCALATE waits for the owner.

### L3-RV-TX-3FC2FA1D-SEMANTIC-FACET - lookup_ts swallows history.get errors as unknown age with no log

- Verdict: `PARTIAL`; risk `low`; fix size/kind `M/code`; **OWNER DECISION**.
- **Decision: IMPLEMENT** (@oh design decider, 2026-10-30; compat `compatible`, risk `medium`). Add pub(crate) async fn try_lookup_ts(&self, version) -> DbResult<Option<u64>> in crates/shamir-tx/src/mvcc_store/history/mvcc_history.rs. It returns Ok(None) for DbError::NotFound and for a value that is not 8 bytes long (current behaviour), Ok(Some) for a valid stamp, and Err for any other storage error. The existing lookup_ts becomes a thin wrapper: warn and return None. The reporting paths propagate: when get_many fails, history_of (:241-249) and history_many.rs (:100-106) retry individually with try_lookup_ts and return the first retry error, as the history_of_many doc already promises. Every GC caller in mvcc_gc.rs (:132, :272, :279, :397, :486) keeps the conservative lookup_ts, so an unknown age is still kept. Signatures stay the same (both functions already return DbResult). Successful paths and the pending_ts fast path stay unchanged; get_many returning None for a missing stamp still means ts_millis None. Regression tests with a fault-injecting history store, where both get_many and the per-key get fail with a non-NotFound error: history_of and history_of_many return Err (old code returned Ok with ts_millis None); a NotFound stamp still gives Ok with None; age-based vacuum under the same failure keeps the version. Out of scope: GC policy, timestamp persistence format, the public VersionEntry type.
- Evidence at `07bc804c`: crates/shamir-tx/src/mvcc_store/history/mvcc_history.rs:233-260,923-937; crates/shamir-tx/src/mvcc_store/history/mvcc_gc.rs:271-279
- Recipe: Separate absent timestamps from storage errors, propagating reporting failures while retaining conservative GC behavior.
- Verifier note: Warnings restore diagnostics but reporting still returns absent timestamps after storage failures; preserve conservative GC separately.
