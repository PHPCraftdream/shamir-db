### Binding ruling RU10 — guest SDK raw `Value` filters (RV-SDK-F956C637)

Decided by 2x rush reviewer + @oh (unanimous, 3/3): **option A — keep `Table::get`/`Table::query` as a documented WASM-bridge exception and make the host-side conversion strict.** The builder-backed guest API already exists (`Db::execute(&Batch)` behind the optional `query-builder` feature of `shamir-sdk`, documented as compiling to wasm32 in docs/dev-artifacts/roadmap/SDK_AUTHORING.md), so there is nothing to add; routing `Table::*` through it would force a default-on size increase and still need the same conversion.

Facts: `crates/shamir-db/src/shamir_db/shamir_db/db/db_gateway.rs` (`key_to_filter` / `qv_to_filter_value`) maps every other `QueryValue` variant to `FilterValue::Null`, so a List/Map/Set/Dec/Big key (or a top-level List key on the scalar branch) silently becomes an equality-to-Null predicate and can select a null-valued row. A gateway `Err(String)` already becomes a host error in `crates/shamir-wasm-host/src/wasm/bindings/db.rs`, so the invocation fails visibly; no ABI change is needed.

Acceptance:
1. `qv_to_filter_value` returns `Result<FilterValue, String>`. `Null`, `Bool`, `Int`, `F64`, `Str`, `Bin` map exactly as today. `List`, `Map`, `Set`, `Dec`, `Big` return `Err` with the stable prefix `unsupported key value`, the variant name and the field name (`id` for the scalar branch).
2. No wildcard `_ =>` arm: a new `QueryValue` variant must break the build.
3. `key_to_filter` returns `Result<Option<Filter>, String>`; `get` and `query` propagate with `?` before any `execute_as` call.
4. An empty map still returns `Ok(None)` (match-all; that is the separate card RV-SDK-152055F3); a one-entry map still yields one `Eq`; more entries still yield `And`.
5. Why-comments (the repo rule requires them): one line at `key_to_filter`, one at `Table::get` and one at `Table::query` in `crates/shamir-sdk/src/api/db.rs`: "WASM-bridge exception: guest msgpack `Value` key -> typed `Filter`; use `Db::execute` (feature `query-builder`) for builder queries".
6. Update the SDK docs in `db.rs`: list the accepted key shapes, say any other shape fails the invocation, point to `Db::execute` for anything beyond equality keys.
7. Tests (new file `crates/shamir-db/tests/functions/gateway_key_filter_e2e.rs`, wired in `tests/functions/main.rs`; the `facade/` folder is already at 7 entries, so the file goes at the `functions/` level): in-memory db, table with row A (`tag: Null`) and row B (`tag: "x"`), a native function calling `ctx.db_gateway()`. Assert: `get(Map{tag: List[1]})`, `get(Map{tag: Map{k:1}})`, `get(List[1])`, `get(Map{tag: Set{..}})`, `get(Map{tag: Dec})`, `get(Big)` each return `Err` containing `unsupported key value` and never row A (red on today's code); `query(Some(Map{tag: List[1]}))` and `query(Some(List[..]))` return `Err`; positives: `get(Map{tag: Null})` returns A, `get(Map{tag: "x"})` returns B, scalar `Int` key on `id` works, `query(Some(Map{}))` and `query(None)` return 2 rows.
8. The pagination card RV-SDK-5EAF15D9 changes the `db_query` ABI (new parameters or a new import plus the sanitizer allowlist and linker) and goes in its OWN PR/stage split; do not fold it in here (H9 may do the other cards; the executor must put the pagination card in a separate commit series and say so, or leave it open with a note).

Compat: no wire, disk or ABI change. Behaviour change: an unsupported key used to give a wrong Null-equality result and now fails the invocation (fail closed; a guest cannot catch it, documented in item 6).


## Requirements

1. Before editing, confirm each mechanism in current code (read callers and guards). If a card is already fixed or wrong at HEAD, do not change code for it: say so with file:line evidence in the final message.
2. Fix at the narrowest layer that owns the invariant. No unrelated refactors, renames or comment edits.
3. TDD for runtime cards: add a regression test whose name contains the card's hex suffix in lower case (for example `rv_storage_98f6650d_...`). The test must fail on the unfixed code and pass on the fix — reason about that from the code, you cannot run it. Tests live in the module's `tests/` folder (`tests/mod.rs` is a manifest only; no inline `#[cfg(test)] mod tests {}`) and are registered there. Prefer deterministic constructions (injected failures, barriers, paused clocks) over sleeps and timing. Docs-only, layout-only and comment cards need no test: say so in the final message.
4. House rules: imports at the top of the file; `mod.rs` re-exports only; one primary export per file; at most 7 entries per folder and 1000 lines per source file for new/changed code (check_layout is the gate); Fx hashers; no `std::sync::Mutex`/`RwLock` on hot paths; `Result` instead of panics; no private machine paths in committed files; terse comments; queries only through the query builder.
5. Do not bump crate or dependency versions, do not add dependencies, do not touch CI workflows (except where a card says so).
6. Run only the allowed local gates from the policy (clippy, fmt, layout) on the touched crates until clean. If a changed public signature affects dependent crates, run clippy on those too.
7. Other agents work concurrently on other crates; stay inside the files your cards name plus their tests.
