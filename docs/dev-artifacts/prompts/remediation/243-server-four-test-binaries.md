# 243 — server-four-test-binaries (CI speed #1549, stage A2: shamir-server 49 integration binaries → 4)

Context (@oh ruling 2026-10-29). Each integration-test target is compiled and linked separately; the CI `integration` job (ubuntu + windows) links ~97 binaries and link time dominates. nextest (the only sanctioned runner; bare `cargo test` is blocked by the runner guard) runs every test in its own process, so merging binaries does not change isolation, statics, env or ports. `crates/shamir-server` has 48 explicit `[[test]]` targets plus the autodiscovered `tests/seed_recovery_e2e/main.rs` = 49 binaries, 305 tests (origin/master f9dc5788). Collapse them into 4 binaries — one per existing top-level folder — by `mod`-aggregation, editing only module plumbing, never test logic. Sibling stage 242 (shamir-connect) is disjoint; both land in one PR.

Re-verified facts (f9dc5788):
- `tests/` has 7 entries (admin, common, connection, e2e, misc, repl, seed_recovery_e2e): no new top-level entry is allowed, and `tests/connection` (7 files) cannot take a root. Roots go to `tests/{admin,e2e,misc,repl}/main.rs` (3, 3, 3, 6 entries after).
- 12 single-file targets include the shared harness via `#[path = "../(../)common/mod.rs"] mod common;`. Inside ONE binary that would mount `common/mod.rs` several times → rustc copies it, and rust-guard `modules` reports `DUPLICATE_FILE`. The shared `common` must be mounted exactly once per binary.
- 7 folder targets (`permission_e2e`, `user_directory`, `backup_restore_e2e`, `subscriptions_e2e`, `db_handler`, `hmac_gate`, `seed_recovery_e2e`) have a `main.rs` root whose children use `crate::…` paths. Nested under a group root, `crate::common` would silently resolve to the SHARED harness (or fail) — every such path must become `super::…`.
- rust-guard resolves a `#[path]`-mounted non-`mod.rs` file as non-mod-rs (children in `<dir>/<stem>/`), unlike rustc → a `#[path]` must never target a `main.rs` with child modules: those 7 `main.rs` files are renamed to `mod.rs` (6 are pure manifests).
- `admin/ops/backup_restore_e2e/main.rs` holds a test that re-spawns its own binary with `--exact "backup_unclean_server_restore_certifies_before_serving_pull"`; libtest `--exact` matches the FULL test path, so the string must carry the new module path. This is the only in-code dependency on a binary/test name (grep-verified: no `current_exe` elsewhere).
- No workflow, script or `.config/nextest.toml` filter names a shamir-server test binary (ci.yml/release.yml mention file names in comments only). No `#[serial]`, no env mutation; process-global installs (rustls provider, Prometheus recorder) are already race-tolerant and per-process under nextest.
