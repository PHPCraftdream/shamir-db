### Measurement sequence

For each selected cell:

1. Finish **both builds** before measurement; no compilation or cache upload during timed runs.
2. Run one unreported warm-up process for A and one for B.
3. Run **five measured pairs**, alternating order:
   **AB, BA, AB, BA, AB**.
4. Start a fresh benchmark process for each observation. Do not run benchmark binaries concurrently.
5. For very short/one-iteration cells, use a predeclared common scale multiplier, chosen in a CI pilot, to obtain a useful timed interval. Apply exactly the same multiplier to A and B.
6. Report the median A value, median B value, and **median of paired B/A ratios**. Preserve every raw observation.

Use ten pairs on the dedicated runner for confirming flagged cells and for closing noisy debts. Do not keep rerunning until a favorable result appears.

**INFERRED:** same-runner pairing removes much machine-to-machine variation; interleaving reduces time-order bias. It does **not** cancel transient noisy neighbors, shared-storage jitter, or scheduler effects.

Record CPU model, available CPUs, memory, kernel/image version, compiler version, feature set, profile, thread settings and order. Hold relevant thread settings constant across A/B. Do not claim `taskset`, elevated `nice`, governor changes, or affinity provide hosted-runner isolation; this design does not depend on their availability.

### Initial thresholds

These are **proposed policy margins, not measured runner noise**:

| Class | Hosted flag | Dedicated initial certification margin |
|---|---:|---:|
| Synchronous CPU microbenchmarks: projection, grouping, planning | **15% slower** | **10% slower** |
| In-memory async pipelines and scans | **20% slower** | **15% slower** |
| Contention, task coordination, subscriptions | **35% slower** | **25% slower** |
| Buffered file I/O, fsync, fjall drain | **40% slower** | **25% slower**, only after validating storage stability |

**OBSERVED:** `tx_concurrent` explicitly documents expected ±30% contention variance (`crates/shamir-engine/benches/tx_concurrent.rs:125–128`). The existing absolute gate defaults to 25%; that does not establish a hosted A/B noise floor (`scripts/bench_gate.sh:30–32`).

**Decision rule**

- Flag when the median paired slowdown exceeds the class margin.
- If robust spread of paired changes exceeds half that margin, mark **inconclusive/noisy**, not pass.
- **Hosted timing flags are advisory**, including large ones; they require investigation or dedicated confirmation.
- On the dedicated runner, a slowdown exceeding the margin in two predeclared independent batches is a **performance failure**, unless the owner explicitly accepts the cost.
- Build failure, timeout, benchmark assertion failure, invalid numbers, missing cells, unequal iteration counts, or unexpected calibration are **hard measurement failures on either runner**. They do not mean “performance regression”; they mean no valid answer was obtained.

A result below the margin means **“no regression detected above this margin in these workloads,”** not “no regression.”

**Use immutable Actions artifacts for measured A/B baselines, not a committed absolute timing file and not gh-pages.**

Each run rebuilds and measures A. An artifact from a previous hosted runner is historical evidence, not the denominator of the next comparison. Retain artifacts for 90 days and preserve the accepted certification artifact in the program’s durable records.

## 5. Risks and handling

- **False alarms and false reassurance:** five pairs are a screening experiment, especially across many cells. Use class margins, dispersion and independent confirmation. Keep small “within margin” findings separate from unmeasured cases.
- **Cache poisoning:** maintainer-only dispatch, trusted immutable revisions, no fork execution, no privileged PR trigger, pinned actions, revision-specific caches. Never load executable build caches from untrusted PR runs.
- **Persistent-runner security:** do not register the owner’s desktop. Use a designated isolated machine, preferably disposable/reimaged between runs; read-only repository permissions and no deployment credentials.
- **Time budget:** fat-LTO builds and untimed setup may dominate. Build only named targets, use per-process timeouts, keep huge-read/vector modes off, and upload partial logs on failure. A timeout is not permission to shrink row counts differently on A/B.
- **Secrets:** no repository secrets needed. Disable persisted checkout credentials; do not give benchmarks a write token or cloud/deployment credentials.
- **Baseline compiler incompatibility:** classify **measurement blocked**, never performance pass. First try a common pinned compiler that builds both revisions in CI. If none works, create a reviewed compatibility-only adapter/patch and record its digest. Do not use different compilers for A/B or silently move A forward.
- **Attribution:** this comparison gives the **net series effect** from `e1106477` to the pinned master tip. It cannot identify which remediation caused a slowdown. Follow up with intermediate-SHA comparisons on flagged cells.
