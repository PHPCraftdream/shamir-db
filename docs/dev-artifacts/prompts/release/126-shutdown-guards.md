## What (fix in this order; for each item write the failing test first where a test is possible)

### 1. Item 20: a follower panic skips the wrapper's exit housekeeping (P2, older than the shutdown batch)
In `sync/sync/replication/supervisor/start.rs` each follower is its own `tokio::spawn` task that awaits `run_follower_loop(...)` inline and only afterwards runs the exit housekeeping (`done.store`, the `live` decrement, and for the LAST wrapper the lease invalidation, the registry removal, `torn_down`). A panic inside the loop (for example inside the Hello of a source) unwinds out of the task before any of it: the count never reaches zero, the lease stays valid, `stop_all` removes the descriptor and ignores the failed join. Required: the housekeeping runs EXACTLY ONCE per wrapper on every exit path, including a panic of the loop. Do not put awaiting work into a `Drop`. Suitable shapes: run the loop in an inner task and turn a `JoinError` into the same fall-through (log the panic at error level with the subscription name; a cancelled inner task is not a panic), or `catch_unwind` on the loop future if the crate already depends on what it needs (no new dependency). State what the durable subscription state is after a panic (default: unchanged; the existing terminal mapping stays as it is) and why. Also make `stop_all` (and any other place that joins a wrapper) log a failed join instead of dropping it silently. Tests (put them in a NEW test file of the supervisor test folder; the existing `cfg(test)` seams `teardown_count`, `teardown_done`, `teardown_entered`, `exit_hook`, `registration_hook` exist, reuse them): (a) a one-target subscription whose source panics: after a bounded wait the teardown ran exactly once, the lease is invalid, the registry entry is gone; (b) a two-target subscription where one follower panics and the other exits normally: the teardown ran exactly once in total, after both wrappers ended. Name the mutant each test kills.

### 2. Item 15: audit admission is not one decision (P2)

Keep `close()` and `spawn_tracked` consistent: `close()` must still not return while a spawn decision is in flight. Tests: a refused first visit leaves no principal entry; a contended spawn registry is a counted drop, not a wait (use the existing `arm_*_probe` seams or add a `cfg(test)` seam); name the mutants.
