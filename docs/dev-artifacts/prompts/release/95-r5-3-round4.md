## Replacement test and request boundaries

**Replacement test: the intended denial is the `store_id` comparison, not the second ACL.** The final fixture signs and dispatches with the **same** superuser `Session` (`S/src/engine/db_handler/tests/cursor/get_record_authz_tests.rs:260–323`). The unsigned DTO and the signed builder have the same target and both flags false; the canonical encoder excludes `hmac`, and the verifier derives the key from that dispatch session (`QB/src/ddl/db/drop_table.rs:8–15,55–65`; `QT/src/security/hmac.rs:361–375`; `S/src/engine/db_handler/handlers/admin.rs:659–711`). The superuser passes the coarse DDL gate. The independent DDL handler has an unbounded budget, and its fresh unstamped session does not consume the parked reader’s application slot.

`CREATE TABLE` passes `Actor::Admin(alice)` into table creation, which writes a fresh store ID and owner-only metadata. Admin and User with the same principal encode to the same owner ID, and permission classification compares that number, not the enum variants (`DB/src/shamir_db/execute/admin_ddl/admin_table_index.rs:81–93`; `DB/src/shamir_db/shamir_db/db/table_management.rs:77–106`; `T/src/entries/access/{identity.rs:58,policy.rs:23,resource_meta.rs:46}`). Alice therefore retains Database Read, traversal and Table Read. Under successful setup, deleting **only** the ID comparison changes the expected result to `not_found` from the fresh empty table. To make this self-checking, assert the DDL result fields, distinct live IDs, a fresh read by the **same non-admin principal**, and the fixed changed-registration message on the parked reply. A fresh miss is a useful control; a uniquely seeded replacement row would additionally make the no-payload assertion meaningful.

The park rendezvous has no sleeps: after taking the reader’s slot, the handler captures the config synchronously before awaiting the held budget. The fixture’s 64-byte budget/1,024-byte reservation is deliberately outside launcher validation; the budget implementation admits that reservation once empty (`SEC/src/security/perimeter/byte_budget.rs:250–276,309–317`; `S/src/boot/config.rs:532–543`). **RISK:** the drive helper wraps every child poll in `Poll::Ready`, so its 120-second timeout cannot interrupt the spin; the 100,000-poll limit is the actual fallback (`get_record_authz_tests.rs:198–225`). A pre-slot await requiring the current-thread runtime to schedule other work could fail the fixture before the park. I found no established dependency of that kind in the warmed in-memory setup. The new tests use platform-neutral fixtures and box the wire handler, but compilation, debug stack headroom and execution on Windows/Unix are unverified. The supplied account of two CI setup failures is consistent with the commits, not an independently observed CI result.

**Perimeter and response trace.** Native SCRAM transports use the common authenticated dispatch; follower mode does not skip either ACL, and superusers intentionally bypass ACL bits on **both** calls, not just the second. REST and token WSS deny both variants before native dispatch (`SEC/src/security/perimeter/http_rest/{scope.rs:40,scope.rs:103,executor.rs:78,executor.rs:238}`; `SYNC/src/sync/connection/token_ws/token_loop.rs:343–405`). The native handler has no separate token-origin check on these arms; the perimeter is the gate. After either ACL returns an error, the handler returns before obtaining a user-table handle or consulting the key. The successful point-read path rechecks quarantine on acquisition, reads exactly the key, and hands serialized bytes and the RI-15 guard to the native writer; direct fixture dispatch does not exercise that handoff (`operator_state.rs:262–365`; `SYNC/src/sync/connection/request_loop.rs:352–375`). In an embedded configuration with only a byte budget, a post-read reservation can still wait; there is no subsequent record read. Connection teardown can abort a parked dispatch (`request_loop.rs:430–438`).

`Status` requires actual superuser class, boot context, and a slot for a store-stamped session. Its success DTO contains boot facts, logical names, configured node ID, durability/WAL data and the accepted process-global replication observations—not connection addresses, storage paths, credentials, or principals. Failed override reads return an error rather than a partial DTO, including for `version show`. A typed native catalogue error may contain underlying diagnostic text; the shell does not print it verbatim.

The closed request matches inspected—native dispatch, both perimeter matches, the Rust REST filter and the e2e classifier—handle both variants. Signed-operation matching rejects them as unsupported for signing; the token-admin subdispatcher rejects unrelated variants. Typed SDK methods reject an unexpected reply kind. I found no exhaustive NAPI switch needing an arm; the TS HTTP token transport uses a positive allowlist. The range does not change the wire enum/codec, HMAC encoding, or existing request handling. The only production SDK mapping change is explicit pass-through of these same two success values.

## Layout and fixture lessons

Count every folder you add to with `ls` (many are at 7 entries: `python -I scripts/ci/check_layout.py` counts only tracked files, recheck after staging); at most 1000 lines per file, one primary item per file, `mod.rs` re-exports only (the rust-guard structure gate allows nothing else in a `mod.rs`: shared helpers go in a named file), tests in `tests/` folders, no inline `#[cfg(test)]` modules, no local `use`, no new `#[allow]`. Persistent stores, every `TempDir` alive for the whole test, close handles and wait for the server task to finish before reopening a directory (Windows holds Fjall locks until the dropped engine's background handles finish: reopen with a bounded retry on `Locked` only, like `init_waiting_for_locks` in the function-family crash tests), handshakes not sleeps, every await bounded by a generous timeout (at least 120 s: a hang detector, the Windows runner is up to 10x slower), a batch is at most 50 queries, per-session request rate limit 500 req/s (never poll in a tight loop: pace status polls at 20 ms or more), set `argon2_concurrent_max` and `auth_init_rate_per_second` to 64 in fixtures that open several sessions, debug-test stacks are small (call concrete handlers through `Box::pin`, run deep tests on a roomy thread, `on_big_stack`), assert on invariants and sets, `shamir-test-diag` marks for flake-prone tests.

## Rules that bind the change

* Machine memory: at most ONE cargo command at a time machine-wide (other executors run: if a cargo run is already in progress wait for its notification, never poll), ALWAYS as `bash <orch>/cg.sh env RUSTC_WRAPPER= CARGO_TARGET_DIR=<artefacts>/target-exec/<WORKTREE-SLUG> wnice -p idle -c 50 -t 8 -m 50 -- cargo ... -j 1 > <logfile OUTSIDE the repository> 2>&1` (the wrapper serializes cargo across executors and the target directory is PER WORKTREE (two worktrees sharing one directory made cargo reuse each other's compiled crates and invalidated the gates): use exactly the directory named for THIS worktree and no other, never run `cargo clean`, never create a local `target/` folder; never `-j 2`; never piped through `tail`/`head`; `cargo fmt` rejects `-j`: run it with `CARGO_BUILD_JOBS=1` under the same wrapper); every worker you spawn must be told the same, and no worker may run cargo at all: only you, the top executor, run `check`/`clippy`/`fmt` under these rules (workers edit files and read code only).
* Leave no scratch files in the tree and none outside it (edit only paths inside this worktree).
* Wrap-up: the hard limit is 150 minutes. At about 105 minutes (70%) stop adding scope, bring the change to a compiling, formatted, clippy-clean state and write the final report (what is done, what is missing, what each check printed); a run that hits the limit without a report is lost work.
