## Why

An operator must be able to read who may do what, change ownership and mode of a resource with the server's own authorization still deciding, and find and cancel a stuck request — all from the shell, over SCRAM only (these commands are refused for token sessions with the typed `token_request_denied`).

## What (this step only = PR4)

1. **Read commands.** `user list` (`ListOp::Users` through the existing batch path: permission `Manage(Root)`; the design is explicit that this is not a "List(Users)" permission), `group tree [--db DB]` and `group members` (`AccessTree`; `Manage(Root)` ALWAYS: the optional `--db` filter never narrows the permission), `rights show PATH` (the local selector of §4.5 over the `AccessTree` result: Root / database / store / table / function; a folder or namespace path is not promised if absent from the authorized tree; the shell type-checks the path client-side so garbage never reaches the wire, the server remains the sole authority). Output: supported paths and metadata only; no synthesized effective ACL.
2. **The signing seam (the only edit outside the shell and its tests; list it as a widening).** `Chmod`/`Chown`/`Chgrp` require a per-session HMAC over the exact typed resource (`crates/query/shamir-query-types/src/security/hmac.rs`: the canonical helpers; the server check in the gate and the access handlers). Today the builders (`crates/query/shamir-query-builder/src/.../access_builders/resources/{chmod,chown,chgrp}.rs`) accept only an externally supplied tag. Add a small typed signing entry to EXACTLY those existing builder files and the Rust client (`api.rs`) reusing the existing canonical helpers (no re-implementation of the canonical bytes, no new file; `api.rs` is near its line cap: recount and factor into an existing file if needed; `client/src/client/` is at its folder limit). The key comes from the live session (the Rust client already holds the session HMAC key for token-bearing writes: read how existing signed ops obtain it), never from argv or a file. Proved by a test that the signed request is accepted by the real server and that a wrong or missing tag is refused.
3. **Mutation commands.** `chmod PATH MODE`, `chown PATH OWNER`, `chgrp PATH GROUP` for database / store / table / function targets only (no Root mutation: refuse locally with the typed message, exit code per §5). Interactive confirmation (TTY) or `--yes` in batch BEFORE the HMAC is computed or anything is sent; mode parsed strictly (octal, bounds); owner and group are names resolved by the server (the shell never fabricates ids). The server's refusals (permission denied, unknown target, bad owner) surface as typed shell errors without raw server strings.
4. **Activity.** `activity sessions` and `activity requests` via `ListActivity` (kind Sessions / Requests, scope `Own` by default; `--all` selects scope All and is refused by the server for non-holders of `ActivityView:Manage`: the shell shows the typed denial), paging through the continuation with the shell-side row cap and a typed truncation marker; rows shown with the minted handles only. `activity cancel REQUEST_ID` via `CancelRequest`: confirmation or `--yes`; prints the `CancelOutcome` (`cancelled`, `already_finished`, `already_committing`, `not_cancellable`) as a typed result; note in the help text that a cancel must arrive on another session than the one running the request (the shell's own connection is always a second session). No tx/cursor/shape commands (out of R5: R4b steps 3–4 are not consumed here).
5. **Token behaviour.** Every command of this step is outside the token read-only subset: refused with the fixed `token_request_denied` message, exit 4, ZERO requests sent (the allowlist of PR2 already refuses unknown commands: add tests, and update the catalogue/help so the new commands are listed as SCRAM-only).
6. **Tests (CI-only; `tests/admin/shell/access_activity.rs` is ADDED here: the folder goes from 5 to 6 entries; recount with `ls`; `mod.rs` declarations only).** On the PR1–PR3 harness: `user list` / `group tree` / `rights show` golden structure and the permission split (an ordinary user gets `permission_denied` for each, a user holding `Manage(Root)` succeeds; `--db` does not narrow the permission); the local selector (Root accepted locally, never sent as a `ResourceRef`: assert on the request the server saw); `chmod`/`chown`/`chgrp` happy path with the effect visible in a subsequent `rights show`, refusals (no confirmation in batch without `--yes` → exit code per §5 and nothing sent; wrong HMAC; non-superuser; unknown target; Root target refused locally), and the seam's unit tests in the builder crate (canonical bytes equal the existing helper's, a deliberately altered resource changes the tag); activity: an admin session lists its own and another session's rows (`--all` with and without `ActivityView:Manage`), pagination to exhaustion with a small cap, `activity cancel` of a request running on a second session (a deterministic long-running request: use the existing record-lock park or a wait the R4b tests use; assert the SET of outcomes), `already_finished` for an unknown id; privacy: the secret-leak byte-scan and malicious-peer reflection scans extended to the new commands (no token, no HMAC key or tag, no raw server string in stdout/stderr/argv/profile); token sessions refused with zero requests (counting proxy or server counters). Three-OS runtime proof is a later `workflow_dispatch` on the same head: say in the report which commands the orchestrator must dispatch.
7. **Guide.** Extend the shell section of `docs/guide-docs/guide/07-operations.md` (Russian): the rights and activity commands, permissions, confirmation and `--yes`, the signed-mutation behaviour (what is signed and why, never printed), the second-session rule for cancel, the SCRAM-only note. Typed shell invocations only. Every statement must match the code.
8. **CI selection:** check `scripts/ci/matrix/` selects the changed crates' tests on the three OS (the builder crate gained code); widen only where a target is not selected, and list it.

## Layout and fixture lessons

Count every folder you add to with `ls` (many are at 7 entries: `python -I scripts/ci/check_layout.py` counts only tracked files, recheck after staging); at most 1000 lines per file, one primary item per file, `mod.rs` re-exports only (the rust-guard structure gate allows nothing else in a `mod.rs`: shared helpers go in a named file), tests in `tests/` folders, no inline `#[cfg(test)]` modules, no local `use`, no new `#[allow]`. Persistent stores, every `TempDir` alive for the whole test, close handles and wait for the server task to finish before reopening a directory (Windows holds Fjall locks until the dropped engine's background handles finish: reopen with a bounded retry on `Locked` only, like `init_waiting_for_locks` in the function-family crash tests), handshakes not sleeps, every await bounded by a generous timeout (at least 120 s: a hang detector, the Windows runner is up to 10x slower), a batch is at most 50 queries, per-session request rate limit 500 req/s (never poll in a tight loop: pace status polls at 20 ms or more), set `argon2_concurrent_max` and `auth_init_rate_per_second` to 64 in fixtures that open several sessions, debug-test stacks are small (call concrete handlers through `Box::pin`, run deep tests on a roomy thread, `on_big_stack`), assert on invariants and sets, `shamir-test-diag` marks for flake-prone tests.

## Rules that bind the change

* Machine memory: at most ONE cargo command at a time machine-wide (other executors run: if a cargo run is already in progress wait for its notification, never poll), ALWAYS as `bash <orch>/cg.sh env RUSTC_WRAPPER= CARGO_TARGET_DIR=<artefacts>/target-exec/<WORKTREE-SLUG> wnice -p idle -c 50 -t 8 -m 50 -- cargo ... -j 1 > <logfile OUTSIDE the repository> 2>&1` (the wrapper serializes cargo across executors and the target directory is PER WORKTREE (two worktrees sharing one directory made cargo reuse each other's compiled crates and invalidated the gates): use exactly the directory named for THIS worktree and no other, never run `cargo clean`, never create a local `target/` folder; never `-j 2`; never piped through `tail`/`head`; `cargo fmt` rejects `-j`: run it with `CARGO_BUILD_JOBS=1` under the same wrapper); every worker you spawn must be told the same, and no worker may run cargo at all: only you, the top executor, run `check`/`clippy`/`fmt` under these rules (workers edit files and read code only).
* Leave no scratch files in the tree and none outside it (edit only paths inside this worktree).
* Wrap-up: the hard limit is 150 minutes. At about 105 minutes (70%) stop adding scope, bring the change to a compiling, formatted, clippy-clean state and write the final report (what is done, what is missing, what each check printed); a run that hits the limit without a report is lost work.
