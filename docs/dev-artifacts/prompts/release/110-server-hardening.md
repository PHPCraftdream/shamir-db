## Why

Offline commands (the token CLI, restore) must not create or write files before their preconditions and locks hold, and must not be able to write non-audit bytes into the audit log namespace; the output-path guard must compare directory IDENTITY, not path components; the concurrency tests of the Argon2 gate must be able to fail against the mutants they claim to kill; the guide and the protocol text must say what the code does.

## What

### A. Offline CLI and secret output (#1991). Fix in this order; for each item write the failing test first where a test is possible

1. `main.rs` `run_async` initializes tracing BEFORE it dispatches an offline command (token CLI, restore, ...). The file sink opens with create+append, so a configured diagnostic log creates a file before the lock refusal, or before a restore refusal inside an initialized target, and a diagnostic log pointed at `audit.log` can write non-audit bytes there. Fix: no file sink for an offline command before its preconditions and its lock hold; refuse a sink path inside the `audit.log*` namespace of an audit directory (decide the exact rule from the code: name the namespace by the same helper the audit appender uses, do not copy a pattern). Test: an offline command that is refused by its lock creates no file at the configured diagnostic log path; a sink configured inside the audit namespace is refused with a typed error.
2. `server/boot/policy/token_cli/secret_output.rs` compares canonical path COMPONENTS, not directory identity: a Unix bind-mount alias of `data_dir` passes the `audit.log` prefix guard when the active file is missing after an interrupted rotation. Fix: compare identity (device and inode on Unix, volume serial and file index on Windows) of the nearest existing ancestor directory with the audit directory; keep the component comparison only as the fallback when no identity is available and say so in a comment. Unix-only and Windows-only code gets its `cfg` on the item AND its imports.
3. `reserved_under` ignores ASCII case for the WHOLE directory prefix (case-insensitive only where the filesystem is: make it follow the platform, not blanket); a trailing separator is dropped when a missing destination is rebuilt from components (`token.out/` creates `token.out`: the trailing separator means "a directory", refuse it); the checkpoint-error branches of `run_create` leave the exclusively created output file behind (remove it on every error branch after the exclusive create, and only that file: identity-checked).
4. `SequenceExhausted` does not latch, so an offline finish can report success though a token event was not audited. Fix: latch the exhaustion and make the finish report the failure (the exit code of the offline command must be non-zero and the message typed). Test with an injected exhausted sequence.
5. Visibility narrowing (the rust-guard gate allows narrowing, not widening): `prepare_dir_and_lock`, `ordered_archives_with_suffix`, `decode_checkpoint`, `escape_field` in `sec/observability/logging/audit_appender/` (and the call site in `token_cli/commands/create.rs`): narrow each to the smallest visibility that compiles, after grepping every caller in all crates and tests; if a test needs one, say which and keep it only as wide as that test needs.
6. Fifth-review P3 notes. The guide (`docs/guide-docs/guide/07-operations.md`, Russian) says the clamp-failure warning repeats at every rotation and that deletion happens at the next rotation: that is true only while the mtime is still readable and in the future, and only at a successful retention-enabled rotation: state exactly that. The `sweep_retention` doc still says the sweep stops at the clamped archive although the tail loop continues: correct the doc comment. The symlink check before the clamp write-open is not atomic with the open: document it as a maintenance-lock-model limit next to the code and in the guide (do not try to close it). The Windows regression `create_refuses_a_windows_drive_like_final_component` accepts any `OutputPathError`: pin the exact variant (`Unresolvable` or `InvalidInput`: read which the code returns on Windows and pin that).

### B. Argon2 semaphore tests and wording (#1994; full text in `<artefacts>/review_argon2_4.txt`)

Tests in `connect/tests/security/argon2_semaphore_tests.rs` (check the line count first: split into a new file if the change would pass 1000 lines):

1. The wake-up test: the release is not forced into the gap, so under a delayed releaser a mutant without the mutex passes; `RELEASE_GRACE` of 500 ms is part of the oracle; a releaser delayed by 10 s after registration gives a false failure; the reapers swallow a worker panic. Rewrite with a handshake that makes the release land exactly between the check and the park (no sleep, no grace constant in the oracle), and make a worker panic fail the test.
2. Both public queue tests accept an UPDATED budget (a mutant that uses only the wall clock passes; a mutant that updates both budgets and pauses the task for 3 s passes); they do not isolate the monotonic expiry from the wall-clock expiry; the cancellation case does not assert the refusal reason. Fix each with an injected clock or controlled time source (look for the seam the production code already has; do not add a production seam unless there is none: say so) and assert the reason.
3. P3: the fast-return probe can take a poisoned mutex for a return without blocking; the fixture counts an under-collected permit as collected; the sentinel test does not catch removal of the fast path; the slice test has a comment that says 750 ms against a step of 100 ns (make comment and step agree).
4. For every test you rewrite or add: the mutant it kills, and why it fails on the parent commit. A test whose oracle cannot fail is the defect class of this review: do not produce another one.

Docs (P3), every statement must match the code: `docs/guide-docs/guide/07-operations.md` around the Argon2 section: the remainder formula (`Instant::elapsed` is not the remainder; the remainder is `min(deadline - wall_now, 3 s - elapsed)`); `docs/guide-docs/client-server-protocol-spec/AUTH_PROTOCOL.md` around line 514 (different probes) and the bootstrap-token life cycle: the hash is over the encoded text of the file, a metadata write failure is only a WARN, the cleanup at the next load is best-effort and also happens after a successful rotation, two concurrent logins can both enter the rotation, issuance checks the configured name, the WARN contains the name and the path, TOFU is not out-of-band delivery; throttling: 429 also for the source's concurrency slot, native throttling before the first frame. Documenter's tail: `bootstrap_token_ttl` in section 11.2.2 of the protocol spec; `docs/guide-docs/client-server-protocol-spec/diagrams/01-initial-auth.md` around line 73; the figures of `CAPACITY_PLANNING.md`; the constant name in the comment in `rate_limit.rs`. For each, open the code, decide what is true, write that.

## Review lessons (apply before you report; every one of these defect classes was found by independent reviews of earlier steps)

* An oracle that cannot fail: for every new test name the mutant it kills (the code line you would remove or flip) and why the test fails on the parent commit. A test that passes without the fix is not a test of the fix.
* A fixture that clears its own fault, a negative control that cannot go red, a sleep used for synchronization (handshakes, injected clocks and bounded awaits only), an unbounded await in test setup, a `TempDir` that is dropped before the test ends.
* A statement in the guide, a design text or a comment that exceeds what the code does: every sentence you write or leave must match the code you can point to by `path:line`.
* A test or a mechanism cited in the report that does not exist: before the final report grep EVERY test name you cite, in the changed files, and print the grep result per name.
* The rust-guard `structure` gate fails the change when the visibility of an EXISTING item is widened (new items are fine) and on any new `#[allow]`, inline `#[cfg(test)]` module, local `use` or logic in a `mod.rs`: avoid all of them; list every widening and every new cross-module item in the report.
* A finding fixed at one site while its sibling sites keep the defect: for each fix grep the whole class (same helper, same pattern, same file family) and either fix every site or say why a site is different.
