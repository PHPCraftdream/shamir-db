## Why

The operator can see who runs what right now (R4b-1) and stop it (R4b-2/3), but cannot answer "which kind of query is slow or failing": a per-repository histogram has no shape. Shape statistics group executions by structure with every literal removed, so an operator sees "`orders` filtered by `status = ?` ran 40 000 times, 2 % failed, 9 s total" without any user data in the answer.

## Decisions already taken (do not reopen; implement, and list in the report anything the code forces you to change)

1. **Unit of a shape = one data op execution** (`BatchOp::Read`, `Insert`, `Update`, `Delete`, `Set`). `Call` and every other op are NOT tracked in this step (say so in the guide). One execution is recorded at the SAME point and cadence as the existing per-op duration histogram (`observe_op` in `engine/query/batch/runner/query_runner/runner.rs`, called from `engine/query/batch/control/receipts/propagation.rs`): no extra per-row and no extra async layer on the recursion path (the per-op future is large; keep the recording synchronous and small like `observe_op`). `total_nanos` is the elapsed time `observe_op` already measures; `errors` counts executions whose result is an error (any error code).
2. **What is recorded.** Only an op that reached its execution arm with a RESOLVED table that the caller was authorized to use. An op that fails before that (unknown table, permission denied, validation) is not a shape: otherwise any caller could pour arbitrary names into the registry. Find the cheapest correct place (the arm with `DataArm` has `table` and `interner`; `observe_op` has the entry and the error): decide, state the decision with `path:line`, and prove it by a test (an unknown-table read and a permission-denied read leave `shapes_tracked` unchanged).
3. **Shape key** = 128 bits from TWO passes of `shamir_collections::THasher` (Fx) over the canonical byte encoding, two fixed different seeds, no new dependency. Feed the bytes incrementally into the two hashers (no `Vec<u8>` of the whole encoding, no per-node allocation; a `SmallVec` scratch is acceptable). The encoding: a 1-byte op-kind tag; the table name (hash of its bytes: it is a catalog name, not an interner key); then the structural clauses. For a `Read` fold the filter tree (operator discriminant per node, interner keys of every field path, the shape of nested `And` / `Or` / `Not`, `Between` / `In` arity as a count, NOT values), the projection field keys, the order-by keys with direction, group-by keys, join kinds with their on-field keys, and the PRESENCE (not the value) of limit and offset. For `Update` / `Delete` the filter tree plus, for `Update`, the set-field keys (not values). `Insert` and `Set` fold the op kind and the table only (no payload). Every literal and parameter value becomes a 1-byte type tag (null, bool, int, float, string, binary, array, `FieldRef` (plus its interner keys), `FnCall` (plus the hash of the function name and the arity), `Expr`, `Cond`, `QueryRef` (tag only, never the alias), `Param` (tag only, never the name)). The walk is depth-bounded by `MAX_FILTER_DEPTH`; a deeper tree folds its remainder as one fixed "too deep" tag. Read the real `Filter` / `FilterValue` / `Query` definitions and the existing walkers (`eq/query/filter/caches/field_path_cache.rs` `prescan_filter` and `prescan_field_path_cache`, `eq/query/filter/evaluation/semantics/resolve.rs` `intern_field_path`) for the full variant list; the fold must be an EXHAUSTIVE match (no `_ =>` arm), so a new variant is a compile error, not a silent merge of two shapes.
4. **A field name that is not interned must NOT be interned by the fold.** `Interner::get_ind` returns `None` for an unknown name; fold such a path as ONE fixed "unknown field" tag (so unknown names neither grow the interner nor multiply shapes). Never call a method that interns. A test: ten reads on ten distinct unknown field names fold to one shape and the interner's size does not change.
5. **Registry** per repository: an `scc::HashMap<[u8; 16], ShapeRow, THasher>`, cap 256 rows, a recency tick `AtomicU64`, a single-trimmer guard (`AtomicBool`, the compile-cache trim pattern at `disk_store.rs` `trim_pass`: find it with `grep -rn trim_pass crates/`), `ShapeRow { executions, total_nanos, errors, last_tick }` atomics only, an `(other)` accumulator row. The cardinality mirror is an `AtomicUsize` (NEVER `scc` `len()`: it is O(N) and banned by `clippy.toml`). HARD bound: reserve a slot by a CAS on the mirror BEFORE inserting; a failed reservation folds the execution's counters into `(other)` and requests a trim; the trimmer evicts the lowest ticks down to a low-water mark (for example 224) and folds each evicted row's counters into `(other)` BEFORE removing it. Another scheme is acceptable only if the report proves the bound `rows <= 256` at every instant a reader can observe and a test asserts it under concurrent inserters. The home is next to the existing per-repository metrics (`engine/repo/instance/support/metrics/`, `EngineMetrics`, the `QueryMetrics` trait in its `mod.rs`): a new topic folder `shapes/` there (count entries: the folder has 5, the limit is 7), one primary item per file (`ShapeKey` fold, `ShapeRegistry`, `ShapeRow`, the trimmer, the snapshot type). Add the recording method to the `QueryMetrics` trait only if every implementor and test double compiles (list them); otherwise a separate small trait or a field read through the same `resolver.query_metrics(repo)` seam: choose the smallest, state it.
6. **Reset** zeroes EVERYTHING including `(other)` (design D18: a wipe, not a relocation): swap-to-empty under the trimmer guard, mirror to zero. An observation that starts after the reset lands in fresh rows; an observation racing the reset may be lost (state this in the guide). Reads during a reset see old or empty, never a partial row.
7. **Wire** (`ListShapeStats`, `ResetShapeStats`, in the style of `ListActivity` and `CancelRequest`/`CancelTx`: typed `BatchOp` variants in `qt/ops/batch/ops/batch_op.rs`, a new `qt/admin/shape_stats/` folder for the DTOs, typed `DbResponse` variants in `qt/wire/db_message.rs`, op classification in `qt/ops/batch/core/batch_op_classify.rs` and `op_kind.rs`, the HMAC policy in `qt/security/hmac.rs`, builders in `qb/wire/admin/`, Rust client methods `list_shape_stats` and `reset_shape_stats` in `client/client/api/request.rs` or its sibling, the server handlers beside `server/engine/db_handler/repo_admin/activity/`). Request: `ListShapeStatsReq { repo: String, limit: Option<u32> }` (default 50, clamp to 256) and `ResetShapeStatsReq { repo: String }`. Response: `ShapeStatsPage { rows: Vec<ShapeStatsRow { shape_hex (32 lowercase hex), executions, total_nanos, errors }>, other: ShapeStatsRow-like totals of the `(other)` fold, tracked: u32, truncated: bool }`; order by `total_nanos` desc, then `executions` desc, then `shape_hex` asc, so the page is deterministic; no continuation (at most 256 rows). The reset answers with the existing typed ack shape if one exists (follow `CancelOutcome` / the other admin acks), else a minimal typed ack. An unknown repository is a typed refusal with an existing stable error code (`unknown_db` family or the repo equivalent: reuse, never a new code unless nothing fits; if you add one, say so). Builders only; no raw JSON anywhere.
8. **Permission and audit.** Both ops need `ResourcePath::ActivityView` with `Action::Manage` through the normal authorization path (the shapes aggregate every user's workload, so there is no "own" view), registered like the other activity ops in the coarse-admin-gate exemption and in the token/REST refusal list (`sec/security/perimeter/http_rest/scope.rs` and the token matrix fixtures: token and REST callers are refused for the new ops exactly as for `ListActivity` / `CancelTx`). `ResetShapeStats` destroys evidence: it is appended to the audit chain with the repository name only (reuse the existing admin-op audit path used by `CancelTx` / the token admin ops; no counters, no rows in the audit record); `ListShapeStats` is not audited. Follower policy: follow `ListActivity`'s (the registry is local memory, nothing replicates).
9. **Metric.** `shamir_shapes_tracked` gauge (rows in the registry, not counting `(other)`; cap 256) per repository, exported through the existing engine export path (`sec/security/observability/`, see how `EngineMetrics` snapshots and the repo label are exported; read the `mirror` value, never traverse the map at scrape time). No per-shape labels and no per-user labels (cardinality and privacy). Add the row to the guide's metric description wherever the other R4b gauges are described (do NOT write the full R4a metric catalogue: that is task R4a-6).
10. **Out of scope:** the TypeScript client (a later task), persistence of shapes across restart (in memory by design), per-user splitting, `Call`/function shapes, a `/metrics` family per shape, the R4a metric catalogue, a Grafana panel.
