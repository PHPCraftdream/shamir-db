## Findings

### P2

1. **CONFIRMED — Wall time and monotonic time are sampled on opposite sides of the slot reservation.** `crates/server/shamir-server-security/src/security/user_directory/scram_gate.rs:107–143` reads the wall clock, computes the deadline, and reserves the slot; only then does `crates/net/shamir-connect/src/server/limits/argon2_semaphore.rs:60–65` call `Instant::now()`. If the submitting thread is descheduled for four seconds immediately after the successful CAS and the wall clock steps back five seconds, the slot has already been held for four seconds, but the new `Instant` starts at zero and the wall clock still shows time left. A free permit can be granted and the KDF can start. That is a smaller window than round 2’s blocking-queue gap, but it violates D5’s single admission anchor.

2. **CONFIRMED — The rebuilt wake test detects a lost notification, but does not force the interleaving that loses it.** `crates/net/shamir-connect/src/server/tests/security/argon2_semaphore_tests.rs:55–95` sends the boundary signal *before* `wait_timeout` registers the waiter, then the test thread drops the permit. Remove the release mutex and let the waiter enter `wait_timeout` before the test thread runs: the unlocked release still wakes it and the test passes. Schedule the release first and the same mutant fails. The unchanged mutex probe at `:100–107` independently detects removal of the shared release-helper lock; it does not make this wake test deterministic. Conversely, a correct release can fail the new one-second oracle if the test thread is descheduled after the boundary signal. The main-thread `drop` and raw `join()` are not bounded by the channel watchdog.

3. **CONFIRMED — The public-path test can catch a refreshed deadline, but does not prove zero KDF runs or deterministic cancellation expiry.** `crates/server/shamir-server-security/src/security/user_directory/tests/gate_tests.rs:360–412` uses 64 scheduler yields with no scheduling guarantee, then sleeps four seconds. The sleep need not advance the **wall** clock for the correct implementation to reject: monotonic elapsed time is sufficient, and ordinary runner slowness only spends more of that budget. But the setup can fail before expiry is tested if the task is not polled in those yields. A mutant that refreshes both clocks normally succeeds and fails the test; it can instead pass if it is stalled for another three seconds between refreshing and acquiring, or a forward wall step spends the fresh deadline. Final availability proves no permit **leak**, not no KDF call: a mutant can run the KDF, release the permit, then return counted `Busy`. The cancellation test at `:134–208` was unchanged from `c9e908b0a`; it checks ticket retention and release, not expiry. Specifically, the base has **no** success-or-expiry assertion to replace: it never observes the outcome at all.

**Wait-loop and ownership checks.** A poisoned initial lock at `argon2_semaphore.rs:233` has not consumed a notification. On poisoned reacquisition, `default_wait` drops the recovered guard before the best-effort `notify_one` (`:202–210,277–286`). That branch is **not** literally a locked handoff, but there is no viable waiter that can enter the check-to-sleep gap on that poisoned mutex: new timed acquisitions fail at `lock`, existing sleepers fail on reacquisition, and nothing clears the poison. This is fail-closed, not recovery. On a healthy mutex, an exiting waiter cannot wake itself or forward twice; a live waiter that wakes without a permit parks again without forwarding. This establishes the gate’s handoff, not FIFO fairness or progress with arbitrary external `try_acquire` callers racing it.

`remaining_budget` uses saturating subtraction for the original budget, guards both remaining-time subtractions, and rejects zero or exhausted budgets before attempting. A wall reading behind the admission reading makes monotonic time the tighter bound; a forward step can only reduce the remainder at that sample. `u64::MAX` still bypasses expiry and waits in one-second slices, but clock failure still returns `None`, as before (`argon2_semaphore.rs:241–276,291–295,329–347`).
