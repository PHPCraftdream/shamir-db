## Wire contract (fixed)

Same as the Rust brief, restated:

1. `create_function` gains optional `lang: "wasm" | "rust" | "shamir"` and optional
   `optimize: "auto" | "now" | "never"`. Builders omit unset fields. `"shamir"` is accepted by the type but the
   server rejects it for now (reserved).
2. `{ describe_function: string }`: result record `{ name, lang, origin: string|null, abi: number|null,
   hash: string|null, size: number|null, optimize, tier: null | { tier: 'fast'|'optimized', mode, calls_observed,
   upgrade_state: 'idle'|'scheduled'|'failed'|'done'|'exhausted' }, state: { kind: 'loaded' } | { kind:
   'unloadable', reason } | { kind: 'corrupt', expected, actual } }`.
3. `{ export_function: string }`: result record `{ wasm: string (base64), source: string|null, hash: string }`.
4. `{ check_function: { lang?, wasm?: string (base64), source?: string, optimize? } }`: result record `{ ok: true,
   size, abi, origin: string|null, hash, functions, imports, exports }`; failure is an error result.
5. `{ alter_function: string, optimize: 'auto'|'now'|'never' }`.
6. HMAC canonical form of `create_function` gets two fields appended after the existing `wasm` digest, in this
   order: the **resolved** lang as `e.str(...)` (explicit `lang`, else `'wasm'` when `wasm` is present, else
   `'rust'`), then the resolved optimize as `e.str(...)` (explicit, else `'auto'`). The four new ops carry no
   HMAC. The shared vector fixture is regenerated by the orchestrator: do not edit it, and keep your test code
   reading the fixture exactly as it does today (its `create_function` entries will have `lang`/`optimize` absent,
   meaning the defaults, plus new canonical hex values).

## Deliverables

1. Types (`core/types/schema/ddl.ts`, exports in `core/types/index.ts`): `lang`/`optimize` on `CreateFunctionOp`,
   the four new op types and the four result record types listed above.
2. Builders (`core/builders/ddl/ddl-func.ts`, or a new sibling file if it would pass 400 lines): `lang()` and
   `optimize()` on the create-function builder; new builders for describe, export, check (wasm or source) and
   alter, in the same style as the drop/rename function builders; export them wherever the existing function
   builders are exported (including the client entry that re-exports DDL builders).
3. `core/protocol/hmac.ts`: the `create_function` case appends the two resolved strings (6 above).
4. Docs: `docs/guide-docs/guide/05-functions.md` gains sections for `optimize` (what auto/now/never mean, the
   two-tier compile in two paragraphs, `describe_function` fields), upload and download (`export_function`,
   the exact-bytes round trip, the identity hash and what it is not), `check_function` (dry run, what it
   verifies, no persistence), `alter_function`, the admission limits and allowed wasm features (list them from
   the ADR D2), and the permissions table (describe: Read, export: Write, check: Create plus Execute on the
   compiler for Rust source, alter: Write). Examples use the TypeScript builders only.

## Tests (required, vitest style of the repo; written, not run)

Builder unit tests for each new builder and the new create-function options (omitted when unset); canonical-form
tests: changing `lang` or `optimize` changes the canonical bytes, equal resolved values give equal bytes,
defaults equal explicit defaults; type-level checks where the repo does them. If `e2e-ddl.test.ts` has a clear
pattern for a server round trip, add an e2e file for describe/export/check/alter in the same pattern (clearly
mark nothing as skipped; if you are unsure it can run, say so in the final message instead of guessing).
