## Fixes (in priority order)

1. **CI workflow `.github/workflows/ci.yml` (job `node-binding`).** The upload step uses `if: failure()`, so it also fires when `npm ci` or `npm run build:debug` fails and then uploads the stale committed files. Give the drift step `id: napi-drift` and change the upload step to `if: failure() && steps.napi-drift.outcome == 'failure'`; add `overwrite: true` to the upload-artifact `with:`. Change nothing else in the workflow.
2. **e2e timeouts and hangs (`tests/e2e/tests/21-connection-matrix.test.js`, `tests/e2e/helpers/matrix-server.js`).** The nightly job `node-e2e` has no job timeout and none of the new connects pass timeouts, so one stalled listener hangs the job for hours. Pass `handshakeTimeoutMs: 30000, requestTimeoutMs: 30000` (and `connectTimeoutMs: 10000` where the option exists) in every connect, resume and `connectLocal` call, and `connectTimeoutMs: 10000, requestTimeoutMs: 30000` in the token HTTP/WS option builders and in `login(...)` calls (add a local helper constant). In `matrix-server.js` `stop()` must not hang when the child already exited by signal: check `child.exitCode === null && child.signalCode === null` before waiting for `'exit'`.
3. **Fixed ports.** `matrix-server.js` uses fixed ports 14200-14204; bind `127.0.0.1:0` instead and read each listener's real address, kind and profile from the server's `listener bound` log lines exactly as `crates/shamir-client-ts/src/__tests__/e2e-harness.ts` (`readBoundListeners`) does for several listeners; keep the helper's public shape.
2b. **Strong assertions in the e2e file.** Line ~378: the predicate `!(e instanceof ShamirDbError) || typeof e.code === 'string'` always passes - use `e instanceof ShamirDbError`. The REST-only-token-over-WS case and the superuser-login case have no predicate: use `(e) => /login_account_denied/.test(e.message)` for the superuser login (the core displays `http: status 403 (code login_account_denied)`) and a matching check of the real code for the REST-only token over WS (read `crates/shamir-client/tests/matrix/token/ws.rs` for the real code and status).
3. **Timeouts promised "whole connect" (`src/connect_variants.rs`).** `connectWs` and `connectPlain` spend `handshake_timeout` once on DNS (`bounded(budget, "dns", ...)`) and again inside the core. Compute `let started = tokio::time::Instant::now();` before DNS and pass `budget.map(|b| b.saturating_sub(started.elapsed()))` as the core's `handshake_timeout`. In `resume_with`, wrap DNS resolution and the core resume in ONE `bounded(budget, "resume", async move { ... })`. Keep error mapping as it is.
4. **`connectLocal` handshake timeout.** Add `pub handshake_timeout_ms: Option<u32>` to `ConnectLocalOptions` (Rust) and wrap `core::Client::connect_local(core_opts)` in `bounded(millis(opts.handshake_timeout_ms), "handshake", ...)`; add the field to `js/wrapper.d.ts` and its validation to `js/wrapper.js`.
5. **Token copy in plain memory (`src/token/views.rs`).** `CreatedTokenView` and `LoginView` copy the token into an ordinary `String` (`reveal().to_owned()`). Make the field `Zeroizing<String>` with a `serialize_with` helper (`s.serialize_str(t)`), construct with `Zeroizing::new(...)`, and update `src/tests/error_wire.rs` to build the views accordingly. Document (comment/README, one line) that the msgpack `Buffer` handed to JS and the JS string cannot be wiped.
6. **`caPem` error echo (`src/token/endpoint.rs`).** `TokenTrust::pem(...)` errors can display a line of the PEM input; map every error to the fixed message `caPem: no valid PEM certificate` and never include the underlying error.
7. **Typings and wrapper consistency.** `authKind()` returns `"unknown"` for unknown kinds: type it `'scram' | 'token' | 'unknown'` in `js/wrapper.d.ts` and update `tests/e2e/packaging/consumer.ts`. In `js/wrapper.js` accept `null` like `undefined` for optional fields (`!= null` checks) in `optionalString`, `validateOptionalPin`, `plainLoopback`. Normalise byte inputs (`ticket`, `trustedPin`, `listenerId`) with `Buffer.from(v.buffer, v.byteOffset, v.byteLength)` before calling native when they are not already a `Buffer` (napi's Buffer conversion may not accept a plain `Uint8Array` on every supported Node).
8. **Docs accuracy.** (a) `docs/guide-docs/guide/node-client.md`: build every batch with the TS builder (`Batch.create(id).add(alias, Query.from(...)...).build()`), never with a hand-written `{ id, queries }` object; any SCRAM user may create a token for themselves (`tokens.allow_self_service`, default true), only `forUser` needs a superuser; `connectPlain` has no `serverName` and `connectLocal` takes `addr` - fix the sentence that says all variants take the same parameters as `connect`; document that omitting a timeout keeps the core default and `0` times out immediately. (b) `src/lib.rs` module doc claims "user / API-token administration": only `createApiToken` exists; fix it. (c) `js/wrapper.d.ts`: remove the "as accepted by revoke calls" phrase and the stale header; `js/wrapper.js`: remove the dangling "Wrapped ShamirClient" header. (d) `docs/guide-docs/guide/client-matrix.md`: napi rows 3, 6c, 6d have no napi path (the core has no browser-profile session and no resume over plain TCP): mark them `нет (T9-8)` and fix the note that lists rows 1b, 6d, 6e as T9-8 so it is consistent with napi row 1b being implemented. (e) the "T9-5 report" in `DESIGN.md`: verification needs a dispatch of `ts-e2e-nightly.yml` (the per-PR CI does not run the napi e2e), and state that row 6d was blocked by a missing core API.
9. **Layout and comments.** `src/connect_variants.rs` has three unrelated public option structs plus five functions: move it into a folder `src/connect_variants/` with one file per primary export (`plain_options.rs`, `local_options.rs`, `resume_options.rs`, `connect_ws.rs`, ... as sensible; `mod.rs` re-exports only) keeping `src/` at no more than 7 entries and each file under 1000 lines. In `src/token/http_client.rs` add the one-line "Sanctioned FFI boundary: deserialising a request that arrived as JS bytes" comment before `rmp_serde::from_slice` like `client.rs` has. `src/lib.rs` has an unnecessary `pub use token::{login, LoginOptions};`: KEEP it (it is required so the free function is not dead code under `cfg(test)`), but add a one-line comment saying so.
