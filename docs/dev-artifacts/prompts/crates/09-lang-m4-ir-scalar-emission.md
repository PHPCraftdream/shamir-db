## Deliverables

1. `back/ir/` (design file `back/ir.rs`; it becomes a folder: split types, builder and verifier): flat arenas only (`Vec` plus `u32` newtype ids, no `Box` trees, iterative `Drop`), typed virtual locals (value kinds i32, i64, f64 as in the design: bool and cells lower to i32), basic blocks with explicit terminators (jump, conditional branch, return, trap with error kind), region ids for source loops so the emitter can compute `br`/`br_if` depths, explicit checked-arithmetic ops (add, sub, mul, div, rem for i32/i64 with the overflow, divide-by-zero and MIN/-1 rules of section 2 raising kind 2; f64 arithmetic with the NaN rules of section 2), explicit cell ops (load/store tag and payload, allocate string/list/record, field and element access with bounds checks, optional wrap and unwrap), calls by function index, and the builtin intrinsics of the MVP catalog (`len`, `is_null`, `unwrap`, the six casts with their checked ranges). An IR verifier (`verify`) that checks every use is dominated by a definition, block ends, local kinds match instruction kinds and region ids are well nested; verification failure is `CompileError::InternalInvariant`, never a panic. Bounds: `max_ir_nodes` and `max_operators_per_function` enforced before append (`B001`), fuel charged per IR node.
2. `back/lower/` (folder, new): lowering of every function of the `TypedModule` in `call_order`, statements and expressions exhaustively matched on the front AST kinds, using `expr_types`, `resolved` and `calls` (never re-resolving names). Covers the whole MVP expression and statement language of section 1 for helper and scalar functions: literals (the checker's chosen literal types), identifiers, unary and binary operators with short-circuit `&&`/`||`, equality and ordering by static type (string, bytes, numerics, optionals, lists, records through generated equality helpers), `?:`, record and list literals, field access, list indexing with bounds check, calls, `let`/assign, `if`/`else`, `while`/`for` (range and list), `break`/`continue` through region ids, `return`, `throw string` (kind 1). Definite initialization and returns were proven by M3: the lowering may assume them but must still emit an `unreachable` guard at the end of a non-void function body.
3. Emission (`back/emit/scalar.rs` per design plus split files as needed, `back/emit/module.rs` extended): user functions appended after the runtime helpers in stable index order (`call_order` determines the order; indices must not depend on hash iteration), parameters and results one Wasm value each (i32/bool to i32, i64 to i64, f64 to f64, optional/aggregate to i32 cell offsets), generated equality/ordering helpers only when reachable (the existing `HelperGraph` DCE), static data (string/bytes literals and record descriptors) laid out deterministically with the layout cap `max_static_bytes` and `max_total_literal_bytes` enforced before growth, the runtime-code budget (64 KiB) and the generated-module hard constraints of section 7 (defined functions, types, locals, block depth) guarded BEFORE emission. `emit_runtime_module`'s fixed indices must be generalised minimally and additively; M1 and M5-visible behaviour (the runtime-only module used by the host execution tests in `crates/wasm/shamir-wasm-host`) must keep working byte-for-byte for the existing callers (say in the final message which M1 signatures you changed and why).
4. Scalar ABI (`back/emit/abi.rs`): `shamir_call(ptr, len) -> i64` packed `(out_ptr<<32)|out_len` as already established by M1; for a scalar entry the generated wrapper decodes the call envelope (numeric-key positional values and the redundant `args` list per section 3; follow section 3 exactly, including named arguments if the section defines them for scalars), projects each argument to the declared parameter type (typed projection, missing or wrongly typed values rejected with kind 2/3 as the design says), calls the entry, and encodes the result with the general encoder. Optional parameters: null cell or the underlying value.
5. Public API (design section 6): `api/compile.rs` (`compile(source: &str, options: &CompileOptions) -> Result<CompiledModule, CompileError>`, the only production entry, `pub` and NOT `doc(hidden)`), `api/compiled_module.rs` (`CompiledModule { wasm: Vec<u8>, report: ModuleReport }` using the admission crate's `ModuleReport`), `api/error.rs` (`CompileError` with the four design variants; `thiserror`), and `CompileOptions` extended with `admission: AdmissionLimits` if it is not there yet. Pipeline: size check, lex, parse, `sem::check`, lower, verify, emit, self-admit with `admit_module(&wasm, &AdmissionPolicy::Admission(options.admission))`; an admission failure of our own output is `B002` surfaced through `CompileError::Admission`. `front` and `sem` stay `#[doc(hidden)]` public modules. Compiler fuel: one `CompileBudget` for the whole pipeline (parse already uses it; thread the same budget through lowering and emission, charge before work, `B001` on exhaustion). Determinism: same source and options give identical bytes (a test compiles twice and compares; no timestamps, no address or hash-order dependence in the output or the origin custom section).
6. Tests, registered through owner `tests/mod.rs` manifests, NOT run locally (CI runs them): IR verifier negative cases built by hand; lowering golden checks on the IR of small programs (assert instruction sequences for a few representative functions, not whole-module bytes); emission tests: every compiled test module passes `admit_module` and `wasmparser` validation (test-only dependency already present) and the module respects the section 7 constraints; compile API tests: every `CompileError` variant reachable from source, determinism, limits at 0/exact/exact+1 for the new limits (`max_ir_nodes`, `max_operators_per_function`, `max_static_bytes`, `max_total_literal_bytes`, `compile_fuel`, `max_output_bytes`, `max_function_body_bytes`). Execution tests belong to the host crate and run Wasmtime, which only CI does: add `crates/wasm/shamir-wasm-host/src/tests/runtime/lang/scalar_tests.rs` (register it in the owner manifest; mind the 7-entries rule, use a subfolder if needed) that compiles source with `shamir_lang::compile` and executes the module through the existing host test harness used by `module_tests.rs`, covering: every arithmetic operator with checked overflow, MIN/-1 division and remainder, divide by zero (error kind 2), NaN semantics, all six casts including out-of-range, optional parameters and results (null and present), strings and bytes (equality, ordering, `len`, indexing where defined), lists (literal, indexing, bounds failure, `for` iteration, `len`), records (literal, field access, record parameter and result), nested helper calls, loops with `break`/`continue`, `throw` (kind 1, message preserved), short-circuit evaluation (a right operand that would trap is not executed), the scalar worked example of the design, and a differential section: a small independent reference interpreter in the test code (not reusing compiler code) evaluating random bounded integer/float expressions generated from a fixed-seed generator (write the PRNG inline, no dependency), asserting identical results or identical error kind. Because host tests compare `QueryValue`, add at least a handful of raw-output-byte assertions (shortest integer widths, sorted map keys) for a scalar returning a record and an i64.

## Lessons from M3 (binding)

Every earlier executor claimed "all fixed, verified by reading" and the first CI run still found real bugs: an internal-invariant guard that fired on every valid program with a call (a marker value stored for a non-value node tripped the guard), duplicated diagnostics for one cause, and hand-computed expected strings that were wrong. For this milestone: (1) every guard, verifier check or `InternalInvariant` path you add must be walked mentally against at least three valid programs that pass through it (a call, a loop, an optional) and against the scalar worked example before you call it done; (2) never store placeholder or marker values in a table that a verifier later inspects; (3) when a test asserts an exact string, byte vector, column or index, derive it from the code path that produces it and write the derivation in a one-line comment; (4) one cause, one diagnostic.
