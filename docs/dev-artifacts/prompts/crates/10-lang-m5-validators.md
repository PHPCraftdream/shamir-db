## Deliverables

2. The in-guest representation of the opaque `Validation` value and lowering of the seven constructors (`accept`, `reject`, `reject_path`, `record_error`, `with_error`, `with_record_error`, `stop`) with the exact semantics of the design: `accept` has no errors and `stop=false`; `reject`/`record_error`/`reject_path` append one error; `with_error`/`with_record_error` append in order; `stop` preserves errors and sets `stop=true`. Choose a representation that needs no new runtime helper beyond what the generated-helper graph can reach (an IR-level list of error records plus a bool, built from existing cell operations, is the expected shape); state your choice and why in the final message. Bound the number of accumulated errors by an existing cap or a new documented compiler cap, and growth beyond it raises kind 2, never an unbounded loop or a trap.

## Lessons from M3 and M4 (binding)

Every earlier executor claimed "all fixed, verified by reading" and the first CI run still found real bugs. M4 needed seven rounds on: byte loads need alignment 0; function bodies that end after structured returns need `unreachable` before the final `End`; `select(v1, v2, cond)` returns v1 when cond is true; one Wasm local per IR value; a null cell must not sit in decoder slots; per-node record descriptors; count every `Block`/`Loop`/`If` against its `End`. For this milestone: (1) walk every new branch of emitted control flow on a stack-height simulation by hand for at least the three worked-example vectors before you call it done; (2) never store placeholder or marker values in a table that a verifier later inspects; (3) when a test asserts an exact byte vector, derive it from the code path that produces it and write the derivation in a one-line comment; (4) one cause, one diagnostic.
