## Phase 0 (03d)

Claims are classified as OBSERVED source or INFERRED runtime; no command, build, or test was run.

- **OBSERVED:** `TxContext.write_set` is keyed by table token and holds `StagingStore` (`crates/shamir-tx/src/tx/tx_context.rs:140-147`). `TxContext::ensure_table_staging` uses `StagingStore::new(base)` (`crates/shamir-tx/src/tx/tx_context.rs:890-902`), and `StagingStore::base()` returns `&Arc<dyn Store>` (`crates/shamir-tx/src/tx/staging_store.rs:122-127`). Engine staging passes `self.table.data_store().clone()` (`crates/shamir-engine/src/table/table_manager/transactions/tx_support.rs:164-168`; also `tx_insert.rs:367,582`).
- **OBSERVED:** `TableManager::data_store()` returns the data-store Arc (`crates/shamir-engine/src/table/table_manager/accessors/table_accessors.rs:136-138`). Current `RepoInstance::table_by_token` maps token to registered name, then resolves it by `get_table` (`crates/shamir-engine/src/repo/instance/repo_instance/catalog.rs:121-142`). `remove_table_inner` removes token-name registration and the live table cell (`crates/shamir-engine/src/repo/instance/repo_instance/catalog/repo_membership_impl.rs:320-345`); add re-registers the deterministic token/name (`:298-304`).
- **OBSERVED:** prelock previously scanned touched tokens using `table_by_token_if_live`, which returns `None` when token mapping or live table cell is absent (`crates/shamir-engine/src/tx/preparation/pre_commit/prelock.rs:269-289`; `catalog.rs:168-192`). `TxError::MigrationFrozen { table }` exists and converts to `DbError::MigrationFrozen` (`crates/shamir-engine/src/tx/commit/pipeline/phase/commit/entry.rs:335-336,429`).
- **OBSERVED:** The successful rename retires the old registration after data-store copying; old stores are intentionally orphaned (`crates/shamir-engine/src/repo/instance/repo_instance/catalog.rs:271-280,516-551`).
- **INFERRED runtime:** `Arc::ptr_eq(staging.base(), current.data_store())` identifies the currently registered data-store incarnation because ordinary TxContext staging captures that precise Arc; after rename or drop/recreate, the old Arc differs from the current manager's Arc. A missing registration must reject, not permit a commit into detached backing storage. This inference is directly exercised by new tests, but tests were not run.
- **Correction to prior revision documentation:** revision-2's own Phase 0 errata says M5 affects successful rename and DROP TABLE (`DESIGN.md:41,291`), despite S6 describing it as deferred. Current implementation was read directly; no claim is made that same-name lookup alone identifies incarnation.

## Design (03d)

For each staged data `write_set` entry, prelock resolves the current token registration; absent token returns `TxError::MigrationFrozen` using the staged table name if available. Existing token resolves to a manager; prelock compares the staged base Store Arc with current `data_store()` by pointer identity and rejects mismatch. Thus token disappearance and same-name recreation both fail closed. This check is limited to data staging entries; sidecar-only tx tokens remain covered by existing touched-token prelock behavior and are outside M5's stated staged-data-store identity problem.

No visibility was widened. Existing dormant-table behavior and sidecar union are unchanged. No commands or tests run; CI must compile and execute the four tests.
