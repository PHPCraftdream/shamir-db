# TOKEN-T5b-Rust design and progress

## Design

The four builders are exposed as `shamir_query_builder::token_admin::{create_api_token, list_api_tokens, revoke_api_token, revoke_user_tokens}` and return their typed builders, whose infallible `.build()` methods produce `DbRequest`. `create_api_token(label)` supports `.ttl_secs(u64)`, `.mode(ApiTokenMode)`, `.channels(ApiTokenChannels)`, `.databases(impl IntoIterator<Item = impl Into<String>>)`, `.for_user(name)`, and `.hmac(tag)`; list supports `.for_user(name)` and `.hmac(tag)`; token revoke supports `.hmac(tag)`; user-token revoke supports `.user(name)` and `.hmac(tag)`.

`Client` exposes `create_api_token(&self, request: shamir_query_builder::token_admin::CreateApiToken) -> Result<CreatedApiToken, ClientError>`, `list_api_tokens(&self, for_user: Option<&str>) -> Result<Vec<ApiTokenView>, ClientError>`, `revoke_api_token(&self, id: &str) -> Result<(), ClientError>`, and `revoke_user_tokens(&self, user: Option<&str>) -> Result<u64, ClientError>`. New public wire item `CreatedApiToken` has the prior creation fields and is re-exported with token-admin types; the builder module and functions are public at the paths above. Every client method signs its request; server authorization remains authoritative.

The `DbResponse` type is internally tagged by `kind`. The wire test defines the legacy struct-variant mirror, encodes both it and the new `ApiTokenCreated(CreatedApiToken)` form, and asserts byte equality; it also decodes legacy bytes into the new response and checks the payload (`crates/shamir-query-types/src/wire/tests/db_message_tests.rs:72-153`). This is a tested compatibility argument, not a runtime test result from this run. Deviation: the private signing helper cannot be directly re-exported, so one `#[cfg(test)]` wrapper in `api.rs` delegates to it for vector tests (`crates/shamir-client/src/client/api.rs:399-413`). No new cryptographic primitive or authorization comparison was added: signing reuses the existing session-derived key and HMAC-SHA256 APIs; the creation-token ID check is sanity validation only.
