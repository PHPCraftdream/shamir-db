# P1 fix plan (from the 2026-10-24 revalidation)

Source: [P1.md](P1.md), revalidated at master `b0e1ddf7`. Open P1 cards: **301** (`confirmed-open` 276, `partially-fixed` 15, `unverified` 10), by scoped risk: high 12, medium 126, low 135, nit 24, unrated 4. Execution board: [P1-FIX-TASKS.md](P1-FIX-TASKS.md).

## Stage R0 — re-decide against current master first

The P1 verdicts predate the P0 program (#265–#307). For **186** of the 301 open cards at least one evidence file changed since `b0e1ddf7`. Before any brief is written, every open card is re-decided against current `master` (read-only rush reviewer, one pass, same verdict vocabulary); cards that became `fixed`/`refuted`/`not-applicable` leave their stage, P1.md is updated in place, and a stage whose card list becomes empty is dropped.

## How every stage is executed

- One stage = one PR from its own worktree (`worktrees/<slug>`, branch `fix/<slug>`), brief committed first under `docs/dev-artifacts/prompts/remediation/`, executor (`/wrush`) + reviewer pass, orchestrator verifies the diff.
- TDD: each runtime card gets a failing regression test that names the card ID, pushed with the fix (red/green observed in CI, never locally). Docs/layout/nit cards need no test but must be checked in the diff.
- Local gates only: `cargo check` / `cargo clippy -p <crate> --all-targets -- -D warnings` / `cargo fmt -p <crate>` / `python -I scripts/ci/check_layout.py`. No local builds, tests or benches. Merge after the full matrix is green, squash.
- Up to five stages in parallel when their crate sets are disjoint; inside a lane stages run top to bottom. After a stage merges its cards are re-decided and P1.md is updated in place.
- Cards marked for a ruling (below) start only after a binding ruling (two rush reviewers + @oh) is embedded in the brief.
