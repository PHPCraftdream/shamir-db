# P1 fix tasks — execution board

Companion of [P1-FIX-PLAN.md](P1-FIX-PLAN.md) (acceptance per stage) and [P1.md](P1.md) (the cards). Every open P1 card (301) belongs to exactly one task below. Status: `[ ]` todo, `[~]` in flight, `[x]` merged, `[-]` dropped after R0.

## Managing the wave

Session tasks are labelled `[P1-PLAN:<ID>]`; the subject is only a label. Before launching, reviewing or merging a stage, read its row here (lane, `after`, cards) and its acceptance row in [P1-FIX-PLAN.md](P1-FIX-PLAN.md), and the card text in [P1.md](P1.md). Tick the box in this file when the stage merges, and mark `[-]` a stage whose cards all closed in R0.

## Rules for every task

- Own worktree and branch (`worktrees/<slug>`, branch `fix/<slug>`), brief committed first as `docs/dev-artifacts/prompts/remediation/<NN>-<slug>.md`.
- One failing regression test per runtime card, named after the card ID, in the same PR as the fix.
- Local gates only (`cargo check` / `clippy -p <crate> --all-targets -- -D warnings` / `fmt -p` / `check_layout.py`); CI is the test environment; merge when the full matrix is green.
- After merge: re-decide the task's cards (one reviewer pass), update P1.md in place, tick the box.
- A task starts only when every task in its `after` column is merged.
