## Whole-task source and documentation audit

- Initial named test evidence was narrow: `e2e-login.test.ts` had only successful login/ping, wrong-password, and backoff cases; browser and revocation suites exercised browser/revocation/administratively created tokens rather than the full login-issued-token path. Server HTTP-login e2e tests exist under `crates/shamir-server/tests/e2e/http_login/` and provide server-source evidence, not execution evidence for this TS client end-to-end suite.
- Source review found a partial Unicode username implementation: `crates/shamir-client-ts/src/login/protocol.ts:76-91` explicitly notes unpinned JavaScript Unicode tables and performs limited mapping/checks; full Unicode 15.1 UsernameCaseMapped/NFC conformance is not established (`docs/guide-docs/client-server-protocol-spec/TOKEN_LOGIN_HTTP.md:28`).
- Preflight is warning/evidence only and has no acceptance evidence: launcher source counts KDF-ineligible users and emits a startup warning (`crates/shamir-server/src/engine/server/server_launcher/http/launcher.rs:327-351`); no explicit operator acceptance evidence found. The protocol doc says KDF-ineligible existing users should be counted and disclosed (`docs/guide-docs/client-server-protocol-spec/TOKEN_LOGIN_HTTP.md:209`).
- Documentation progress: `crates/shamir-client-ts/docs/TOKENS.md` login guidance, `docs/guide-docs/guide/07-operations.md` login configuration guidance, and `docs/guide-docs/client-server-protocol-spec/TOKEN_LOGIN_HTTP.md` stale implementation status updated.
