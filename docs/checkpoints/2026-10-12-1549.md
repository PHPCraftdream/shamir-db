## Decisions
- chose the layout limits as a ratchet for new/changed code, checked on the diff by the orchestrator, over a CI gate or a repo-wide refactor, because the owner said an automatic full run is too slow, 92 folders and 78 files already violate it, and in-flight PRs would be blocked.
- chose to keep the legacy coupling "reopen-required acknowledgement marks materialization Deferred" (and document it) over the agent's "orthogonal" design, because an existing test and clients rely on it and the change was out of scope.
- chose to split VIS-4 into 4a (embedded direct writes) / 4b (implicit batch receipts + bounded mode) / 4c (metrics + `changes_since`) and VIS-5 into 5a (merged surface) / 5b (per-alias receipts), over single large PRs, so each is reviewable and independent work can run in parallel.
- chose `flush_seed_catalogue()` (no wall-clock budget) over `flush_all()` in seed tests that only need a durable catalogue, because the budgeted clean shutdown timed out on a loaded Windows runner; the production budget stays 15 s.
- chose to keep `visibility_ack_mode = "bounded"` rejected at server startup until VIS-4b closes the outcome-discarding paths; per-request Bounded on receipt-bearing paths is accepted, every other path fails closed.
