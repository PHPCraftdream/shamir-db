## Decisions
- chose the CommitDriver detach-on-drop design (no spawn per commit; suspended future handed to the runtime on drop; CommitTailBarrier + quiesce_commits) over a spawned post-WAL tail, because a per-append cross-task hop was measured at +22% in wal_group_commit.rs and breaks single-poll Mem atomicity; orphan replay stays as the fallback.
- chose a write FREEZE of the migration source (#91) over building write interception (4-5 PRs, little value while the destination is in-memory only).
- chose ONE server-owned limit model (BatchLimits + CEILING + ExecPolicy + ExecScope, all budget checks BEFORE commit_tx) and to enforce byte budget only when ExecPolicy.enforce_result_size (embedded and WASM db_gateway keep old behaviour).
- chose to keep the shipped large profile valid (result cap 100 MiB = engine ceiling) instead of leaving it invalid with a test that expects rejection.
- rejected raising timeouts / ignoring flaky tests: the #69 test hang was a test construction error (parked Serializable committer holds commit_lock), found by naming the stuck phase with a 45 s deadline.
