## Decisions

- **F-17's design**: chose a cheap, precise `keyset_safe` proof
  (`table.count() == 0` at schema-bind time, O(1) stored counter) over
  either (a) a full retroactive backfill-validation scan, or (b) review
  3's own "disable keyset entirely" fallback suggestion — preserves the
  real, tested keyset-pagination performance win for the common/correct
  workflow (schema declared before any write) while fully closing the P0.
- **F-25's oracle-avoidance requirement**: the new bootstrap-TTL rejection
  MUST reuse the exact same `HandshakeError::BadProof`/`register_failure`/
  `audit_emit` mechanism as an ordinary bad-password rejection — no new,
  distinguishable failure shape, to avoid a timing/response-shape oracle.
- **F-26's scope**: reject `SelectItem::Expression` with a typed error
  (`select_expression_not_supported`) rather than implementing a computed-
  expression evaluator — the evaluator is explicitly a separate, larger,
  out-of-scope feature.
- **F-19's scope**: explicitly declined to add a new "strict mode" config
  knob for `restore()`'s log-only directory-fsync-failure handling (an
  intentional, already-documented, `shamir-wal`-precedented design) —
  chose to tighten `KNOWN_LIMITATIONS.md`'s wording instead of adding new
  behavior.
- **Peak-hours fallback protocol** (user-authorized, standing until
  explicitly changed again): when `/crush` refuses/crashes due to the
  provider's peak-hours window, switch to `@sh` (Agent tool, Sonnet high)
  for delegation instead. A one-shot 12:00 alarm to auto-switch back was
  created and already fired/was deleted along with the babysit cron per
  the user's explicit "stop and delete all crons" instruction — so this
  protocol is currently NOT actively enforced by any cron, but the
  underlying user preference (fall back to `@sh` on `/crush` peak-hours
  refusal) was never explicitly revoked and may still apply if `/crush`
  hits the same wall again.
- **Two-crush-collision incident**: resolved by keeping the `keyset_safe`-
  design session (`f17-keyset-schema-gate`) and killing the "disable
