1. **R0-D (#1013+#1023, коммит `5935b346`)** — fail-closed open-path recovery. Добавлен `IndexState::Failed` (append-safe вариант enum). Два сайта в `TableManager::create`'s reopen-path (провал `drop_all` при Building self-heal; провал `restore_on_open`) раньше логировали warning и продолжали как будто восстановление успешно — теперь помечают backend `Failed` (planner-invisible, автоматически считается в уже существующем `degraded_index_count()`). Плюс #1023: backfill `create_unique_index` больше не молча `continue`-ит недекодируемые записи, а абортится с `DbError::Codec` (тот же fail-closed паттерн, что #960).

2. **R0-A (#1006+#1012, коммит `125b7981`)** — registry watermark + admission. `IndexRegistry` (index2) использовал два несвязанных счётчика (`insert_ticket`/`generation`); detereministic `CREATE A → DROP A → stage → CREATE B → commit` терял posting B. Корневой фикс: расширено покрытие `ddl_admission` (`begin_write_barrier`) на `drop_sorted_index`/`drop_index2`/оба branch'а `rename_index` — раньше держали барьер только regular/unique CREATE и unique-branch RENAME. При максимум одной registry-мутации в полёте счётчики слиты в один. **Найден и исправлен настоящий deadlock**, привнесённый самим расширением admission: `create_index_v2`'s tombstone-check шёл ПОСЛЕ барьера — после того как `drop_index2` тоже стал держать тот же mutex на весь body, CREATE блокировался на admission раньше, чем успевал дойти до fast-reject проверки, что таймаутило существующий тест `p03b_index2_name_reuse_rejected_during_drop`. Исправлено переносом check ДО барьера.

3. **R0-C (#1009+#1010, коммит `6602ea4e`)** — registry insert atomicity + cross-family namespace. `IndexRegistry::insert` публиковал `by_id` раньше `by_name` без отката при коллизии — теперь check-before-mutate (безопасно именно благодаря R0-A). Три open-path сайта, раньше глотавшие эту ошибку (`let _ = ...`), теперь валят ВЕСЬ table open с понятной ошибкой при генуинно противоречивых persisted metadata. `CREATE INDEX` раньше проверял существование только в своей ветке семейства — добавлен единый `any_index_exists` preflight под admission во всех четырёх create-путях; DROP/RENAME теперь отказывают (не молча резолвят первое совпадение) при обнаруженной cross-family коллизии. `doctor::verify()` получил два новых чека (registry consistency + cross-family collisions).

4. **R0-B (#1007+#1008, коммит `a73c57c6`)** — самый крупный и рискованный фикс волны. Часть 1: `SortedIndexManager::rename_definition` теперь бампает generation (симметрично register/drop). Часть 2: заменены три разные эвристики ретракции (index2 — вообще нет; sorted — вообще нет; base — byte-length heuristic, уязвимый к ABA) единым механизмом — каждое определение индекса несёт in-memory-only `instance_epoch` (`#[serde(skip)]`, по прецеденту `included_fields_interned`), свежий на CREATE и бампающийся на RENAME; index2 переиспользует уже корректный `BackendEntry.gen` из R0-A. `IndexWriteOp` несёт `Provenance{family, name_interned, instance_epoch}`; один `retract_stale_provenance_ops` для всех трёх reconcile-функций. **Перед диспетчем лично проверил риск для WAL-формата** — `IndexWriteOp` никогда не сериализуется (реальный WAL-тип `WalOpV2` уже несёт неиспользуемое поле `idx_id`, ожидающее ровно эту будущую работу) — фикс подтверждённо безопасен, чисто in-memory. После коммита обнаружился один упавший тест в полном workspace-прогоне (`filtered_ann_low_selectivity_finds_rare`) — расследовано: тест сам документирует известную нестабильность из-за непереопределяемого RNG в `hnsw_rs`, прошёл чисто и изолированно, и в узком 3-крейтовом прогоне — не регрессия.

## Decisions

- Порядок выполнения R0 строго по карте: R0-D (изолированный, быстрая победа) → R0-A (registry watermark, разблокирует остальное) → R0-C (namespace, зависит от admission из R0-A) → R0-B (провенанс, самый рискованный, последний).
- Перед R0-B лично инвестировал время в проверку риска для WAL-формата (не доверился одной пометке в карте "требует проверки") — подтвердил безопасность, что позволило дать агенту точный, менее осторожный дизайн вместо расплывчатого "будь осторожен".
- При найденном R0-A агентом deadlock — не стал откатывать admission-расширение, а исправил первопричину (порядок check-vs-barrier), сохранив полноту purpose-фикса.
- При упавшем `filtered_ann_low_selectivity_finds_rare` после R0-B — не списал сразу на флаку, а: (1) проверил, проходил ли тест в узком прогоне (да), (2) прочитал сам тест на предмет документированной нестабильности (нашёл — unseedable HNSW RNG), (3) перезапустил изолированно (прошёл) — только после этого расследования классифицировал как pre-existing flakiness, не регрессию.
- Не стал продолжать в R1/R2/R3 после закрытия R0 без чекпоинта — несколько следующих тасок (#1011, #1018, #1021, #1020, #1022) явно требуют решения оператора, не код-фикса; естественная точка паузы для checkpoint+review, как и предписывал `/babygoal`.
