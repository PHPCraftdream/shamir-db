## Decisions
- chose the conservative fail-closed crash certification (clean horizon J, `[J+1, H]` gap) plus an offline logical seed for recovery over the exact crash-gap detector: an exact detector needs a WAL format change, an obligation ledger and follower provenance (4-5 PRs) and only removes false positives, while after a certified gap there was no supported way to recover a follower at all.
- chose to keep the strict W-based acknowledgement as the default and add an explicit bounded mode that returns a separate `visibility: Pending` field (not a new `materialization` variant, not an error), gated by a new protocol version so old clients cannot misread it.
- chose a manual same-runner A/B benchmark workflow on hosted runners (baseline `e1106477`) for advisory triage and an owner-designated dedicated runner for certification, over committing absolute baselines or nightly runs.
- chose to make non-transactional table writes wait for W only AFTER releasing their writer-drain/unique-write barrier (waiting inside deadlocks with the replay of a lower orphan), and to leave a version unsettled (orphan replay owns settlement) when Phase 5a/index projection fails rather than marking it Materialized.
- chose to treat the four reviewers' answers as the owner's decisions for engineering questions and to implement them, while leaving release prep (changelog heading, third-party notices, cosign rehearsal that writes to the public Sigstore log), upstream contribution, publication of checkpoint branches and runner provisioning for explicit owner consent.
